Extensions

What Pi Durable's harness offers the model. A switch saves at once; a setting saves with its Save button.

Code mode

codemode

The codemode tool: the model writes a JavaScript script whose tool calls run as nested calls, each judged exactly as a direct call (ADR-0027). Scripts run in the codemode sandbox Worker.

Estimated tokens the tool declarations in the code mode section may use; past it, scripts find tools with searchTools().

Tool search

tool-search

The tool_search tool, which loads a deferred tool for direct use. Off: every tool is offered directly.

Offered tools

offered-tools

Which tools the model is offered without a search: core (coding tools, ask_user, code mode, tool search, t3's tools), code mode only, or everything. Tools not offered stay callable from scripts and by tool search.

Always on

core: about 14.5k tokens of declarations per request; codemode-only: about 3k; everything: every tool direct.

Web tools

web

web_fetch: one public page as Markdown, text or HTML, through an SSRF guard. web_search, when switched on below: a search-capable model behind the model proxy searches and cites its sources (no new key). Both are reads, allowed in every mode (SPI-1054).

Offer web_search. Off by default: each search is a model request on the proxy's spend.

The model that runs web_search's searches through the proxy (Commissary passes its web search tool to Claude, or to Codex as its own).

Todo list

todo

todo: the agent's Task list for the thread, kept in the Session and shown as t3's todo list. It survives compaction and rollover, and plan mode allows it (SPI-1055).

Context management

context

context_notes (named Notes kept across compaction and rollover), context_history (the thread's stored History, from before a Handoff too) and context_rollover (the agent hands off to a fresh context it writes itself). Notes and History stay in the Session's storage (SPI-1056).

When the context nears full, ask the agent to roll over with its own Handoff instead of a generated summary; a compaction that cannot wait uses the last saved Handoff. Off: pi-durable's own summary.

Terminals and Background jobs

termctrl

terminal_start, terminal_send, terminal_stop, terminal_list and terminal_wait: interactive programs (REPLs, TUIs, prompts) as PTYs in the Workspace's container, and bash's background: true. Approvals follow the thread's mode as bash's do; nothing starts a container until a Terminal or a job starts. At most 8 run at once in a Workspace, and they end with its container (SPI-1057).

Offer bash's background parameter: a command still running after 2 s becomes a Background job.

A Terminal's height.

Guardian

guardian

A reviewer model judges risky tool calls (code mode's nested calls too) before they run and blocks the ones whose risk the owner did not authorize; t3 shows the reason. Beside the thread's approvals, never instead of them. Off by default: each review is a model request (SPI-1058).

The Guardian model, through the proxy. A small, fast one: every reviewed call waits for it.

The first pass's thinking; a would-be rejection is checked again at low or above.

Which tools are reviewed, as name=allow|review|deny pairs separated by commas (bash=review, mcp__github__create_issue=allow). Unlisted tools keep the built-in default: bash reviewed unless a Safe Command, edits to Sensitive Paths and terminals reviewed, read-only tools allowed.

Literal command prefixes as prefix=allow|review|deny pairs separated by commas (git push=deny, npm test=allow). deny blocks without a review.

Trusted destinations and forbidden actions, added to the built-in policy the Guardian judges by.

Advisor

advisor

A reviewer model reads the thread's completed work in the background and gives attributed advice (nit, concern, blocker), shown in t3 as Advisor notices. It never starts a turn t3 did not start. Off by default: each review is a model request (SPI-1059).

The Advisor model, through the proxy; inherit follows the thread's model.

turn: after every tool round that is not read-only; a number: every that many rounds and at the end; request: once, when the agent answers.

The Advisor's thinking level.

How often a blocker found as the agent answers continues the same turn to address it (0: never); later blockers wait for the next turn.

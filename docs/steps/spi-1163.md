# SPI-1163: Text generation on any Model endpoint's model

Thread titles, commit messages and PR text now run on any Model endpoint's model, not only through the Model proxy.
The text is one pi-ai request on the agents Worker, called from the Environment DO, so the Environment's bundle never
holds pi-ai. The text-generation setting can name any `<endpointId>/<modelId>`. While the owner has picked no model,
the setting names the default: a small model of the first endpoint that has one. ADR-0034 §5 records the design.

### How the key reaches the request (the brief's question)

**No key crosses the Environment→agents call.** The call carries the endpoint as the Environment stores it now (it has
no secret), the model id and the prompt. The agents Worker then calls `endpointCredential({ endpointId, target })` on
the Environment DO, exactly as a Session does (ADR-0018). The key comes back in that answer, which is the existing
Session pattern.

I chose this because it reuses the target rule unchanged: the Environment gives the key only for the endpoint's
current target. Even a malformed or stale endpoint in the call cannot send the key anywhere else. Passing the key in
the call would have been a second path that the target rule does not guard.

### The subscription seam

A sign-in endpoint (SPI-1164/1165) needs no change here. Text generation builds its request with `endpointProviders`,
the same resolver a Session uses. Once the broker exists, that resolver gets the sign-in's access token for both
Sessions and text generation. The seam is commented in `endpointTextGeneration.ts`.

### Errors

Each failure names the endpoint. The text comes from our own fixed strings, never from the vendor's body:

- **401/403:** "refused its API key (HTTP n): check it in the Harness panel".
- **404:** "does not serve the model m".
- **429:** "is rate- or usage-limited".
- **Other 4xx:** "refused the request".
- **5xx:** "failed (HTTP n)".
- **No answer:** "could not be reached".
- **Timeout:** "did not answer in time".
- **No key:** the same reasons a Session's turn gives (no key, unreadable, changed).

On the Environment side:

- The endpoint was removed: "was removed: pick another model for text generation".
- The endpoint no longer lists the model: "no longer lists the model m".
- An agents-Worker transport error: "the agents Worker could not be reached". The platform's error text is kept only
  as the cause.

The status is read through the request's `fetch`. pi-ai takes a custom fetch only for Anthropic Messages and the two
OpenAI APIs, so Google's and Mistral's failures say less ("did not answer").

`proxyFailure.ts` was not reused: its table is Commissary's own contract (cooldowns, spend limits). The generic status
mapping fits any endpoint.

## Seams tested

- **`defaultTextModel`** (`apps/environment/test/textModel.test.ts`):
  - an endpoint without a small model is skipped;
  - the cheapest known price wins, before unknown prices;
  - the usual families are known (`minimax` is not "mini");
  - with no prices, the first listed small model is taken.
- **`generateEndpointText`** (`apps/agents/test/endpointText.test.ts`):
  - **Success:**
    - one request to the endpoint's URL, carrying its key and headers;
    - the key is asked for the endpoint's target;
    - a no-auth endpoint sends the placeholder key and asks for none.
  - **Status mapping:** each status above on Anthropic Messages, OpenAI Responses and OpenAI Completions. The vendor
    body and the key are absent from every message.
  - **Other failures:**
    - unreachable;
    - each no-key reason, with nothing sent;
    - a model the endpoint doesn't list, with nothing sent;
    - an empty answer.
- **`runText`** (`apps/environment/test/endpointTextGeneration.test.ts`):
  - **Endpoint path:** the call carries the stored endpoint and no key (the proxy key is not in it either); the
    agents Worker's error is passed on; a transport failure names the endpoint, not the platform's text.
  - **Default and proxy:** `default` resolves to the first endpoint's small model; `anthropic/…` still goes to the
    proxy.
  - **Failures with nothing called:** a removed endpoint or model, and no binding.
  - **Nothing usable:** no small model and no proxy gives guidance.
- **The setting's default** (`apps/environment/test/textGenerationDefault.test.ts`, on t3's test settings service):
  - **Replaced:**
    - t3's own default, with Codex registered or not;
    - the old seed (`anthropic/claude-haiku-5-5`), which then follows endpoint changes.
  - **Fallbacks:** the proxy's small model when no endpoint has one; `default` with no proxy and no small model.
  - **Kept:** a model the owner picked, including after the default had been written.
- The existing `endpointModels`, `sessionEndpoints` and `seedSettings` tests pass unchanged.

## Escalations (assumed provisionally)

1. **What "no model set" means for the setting.** t3's setting always has a value, so "unset" is one of:
   - t3's own default, `codex`/`gpt-6-luna`;
   - an unregistered instance;
   - `default`;
   - the model this sync last wrote (stored in the DO);
   - the earlier seed, `anthropic/claude-haiku-5-5`, before any record exists.

   Two consequences:
   - **An earlier explicit pick may be replaced once.** An owner who deliberately picked the proxy's
     `claude-haiku-5-5` before this change sees it replaced by an endpoint's default. The hard cut moves `anthropic/…`
     selections to the default anyway.
   - **Text generation leaves Codex.** On `main` the setting stayed at Codex's model on every Cloud Environment: step
     4a registers a `codex` instance, so the old "unregistered instance" seed never ran (the first p1163 run showed
     this). Text generation therefore ran through the Codex CLI. It now moves to Pi Durable's default. The ticket asks
     for this, but it changes prod's behaviour at the next deploy.

   Recommendation: keep both as built.
2. **The small-model rule:** a word-match on the id (haiku/mini/nano/flash/lite/small/tiny), then the cheapest known
   output price. Recommendation: keep it. The owner can always pick a model, and the setting shows which one is in use.
3. **The default when no endpoint has a small model:** the proxy's small model until SPI-1176. SPI-1176 should drop
   that branch in `textModelOf` and `syncTextGenerationDefault`; after it, the setting reads `default`, which fails
   saying to pick a model.
4. **Reasoning:** text generation sends no reasoning level, so each model uses its own default, with
   `maxTokens = min(model, 8192)`. Recommendation: keep it; revisit if a reasoning model spends the budget thinking.

## What was built

- **M1, discovery and snapshots.** `discoverSkills` takes `roots`, `discoverPrompts` takes command sources (nested
  names joined with `:`, Claude Code's). `WorkspaceDO.skills(cwd, agent?)` and `prompts(cwd, agent?)` answer at a CLI
  agent's roots, without Environment skills (SPI-1153's). The four CLI drivers get `snapshotForCwd`
  (`cliSnapshotForCwdOf`): the CLI's Repo skills (scope `project`, t3 paths) and its repo commands after the machine
  snapshot's built-ins. From the Workspace DO; never a spawn, never the Container. The Harness `skills` switch is Pi
  Durable's and does not gate them: the CLIs load their Skills whatever it says.
- **M2, pi.** The profile appends, before `--no-approve` and from `CLI_ROOTS.pi`, `--skill <cwd>/.pi/skills`, then
  `--skill <dir>/.agents/skills` for each directory from the cwd up to the Workspace's repo root (nearest first), and
  `--prompt-template <cwd>/.pi/prompts`; t3 may not send either flag. A thread's cwd can sit below the repo root: a
  project may be added at a subfolder of a Workspace (`/w/<id>/pkg` locates in Workspace `<id>`); a worktree's root is
  its own path. Discovery agrees (a `cwdOnly` root; `discovery.test.ts`, `cliProfiles.test.ts`). Trust stays off, so
  the repo's extensions, settings and packages do not load. An absent root is only a diagnostic pi keeps (RPC mode
  prints none), so every root is named, not only those that exist.
- **M3, mentions.** Claude Code: `claudeSkillText` (`provider/cli/claudeSkills.ts`) over stock's
  `planClaudeSkillDispatch`, applied in `wrapCliAdapter`'s `startTurn` (`rewriteTurnText`) with a fresh read of Claude's
  Skills. A mention that opens the message becomes `/name rest`, which t3's ACP adapter sends alone as a native Slash
  command (stock's form for a sole mention). Every other mention becomes an inline `/name` with a note in stock's
  wording naming its `SKILL.md`, first time per Skill. So `$a … $b` goes as `/a … /b [note]`: `/a` expands natively
  and carries no redundant note; Claude expands one Skill a message, and `b`'s note has the agent read it. Stock
  differs: it notes only an earlier user-only Skill and sends the last mention as a native block of its own, which one
  ACP text cannot carry (U65). OpenCode: SPI-1147's embed, switched on in its `buildPrompt` (`acpPromptBuilder`), with the turn's cwd from
  the wrapper (`CliTurn`); the block is what OpenCode's skill tool returns (`<skill_content>`, body, base directory),
  in t3 paths; no Prompt templates (OpenCode's commands reach it as typed). Codex and pi need nothing: Codex parses
  `$name`; t3's pi extension embeds what pi loaded.
- **M4, built-ins** (`provider/cli/builtInCommands.ts`, in each machine snapshot): `/compact` for Codex and pi, Codex's
  `/goal`. Never `/feedback`.
- **Prompt templates' discovery** for CLI sources skips a nested source's dot directories; the Durable agent's
  `.pi/prompts` path is unchanged from SPI-1147 (a dot-named file there is still a template; `templates.test.ts`).

## What was built

- **M1, discovery and snapshots.** `discoverSkills` takes `roots`, `discoverPrompts` takes command sources (nested
  names joined with `:`, Claude Code's). `WorkspaceDO.skills(cwd, agent?)` and `prompts(cwd, agent?)` answer at a CLI
  agent's roots, without Environment skills (SPI-1153's). The four CLI drivers get `snapshotForCwd`
  (`cliSnapshotForCwdOf`): the CLI's Repo skills (scope `project`, t3 paths) and its repo commands after the machine
  snapshot's built-ins. From the Workspace DO; never a spawn, never the Container. The Harness `skills` switch is Pi
  Durable's and does not gate them: the CLIs load their Skills whatever it says.
- **M2, pi.** The profile appends `--skill <cwd>/.pi/skills --skill <cwd>/.agents/skills --prompt-template
  <cwd>/.pi/prompts` before `--no-approve`, from `CLI_ROOTS.pi`; t3 may not send either flag. Trust stays off, so the
  repo's extensions, settings and packages do not load. An absent root is only a diagnostic pi keeps (RPC mode prints
  none), so every root is named, not only those that exist.
- **M3, mentions.** Claude Code: `claudeSkillText` (`provider/cli/claudeSkills.ts`) over stock's
  `planClaudeSkillDispatch`, applied in `wrapCliAdapter`'s `startTurn` (`rewriteTurnText`) with a fresh read of Claude's
  Skills: a sole mention that opens the message becomes `/name rest`, which t3's ACP adapter sends alone as a native
  Slash command; otherwise every mention becomes an inline `/name` with stock's note naming its `SKILL.md` (first time
  per Skill). OpenCode: SPI-1147's embed, switched on in its `buildPrompt` (`acpPromptBuilder`), with the turn's cwd from
  the wrapper (`CliTurn`); the block is what OpenCode's skill tool returns (`<skill_content>`, body, base directory),
  in t3 paths; no Prompt templates (OpenCode's commands reach it as typed). Codex and pi need nothing: Codex parses
  `$name`; t3's pi extension embeds what pi loaded.
- **M4, built-ins** (`provider/cli/builtInCommands.ts`, in each machine snapshot): `/compact` for Codex and pi, Codex's
  `/goal`. Never `/feedback`.

## Decisions made here (for the orchestrator)

1. **Not listed, after the stage runs** (the ticket's rule for built-ins, applied to what failed):
   - `/compact` for Claude Code and OpenCode: t3's ACP adapter answers "This provider does not support /compact"
     (our flavors set neither `supportsCompaction` nor `compactSession`). Making it work is a flavor change, not this
     ticket's.
   - OpenCode's repo commands: OpenCode 2.2.7 over ACP ends a command's turn once submitted (`acp/turn.ts`), and its
     reply never reached t3, not even 30 s later (`opencode.json` `steps.command`, `commandLateReply`). `CLI_ROOTS`
     still records OpenCode's command directories (the probe holds them); the snapshot omits them.
   **Escalation candidate**: listing them anyway would offer a command whose reply the owner never sees.
2. **Claude Code, more than one mention**: native `/name` only when the message's one mention opens it (stock's
   `leadingText === undefined`); with several, every one gets the note, since Claude expands one Skill per message.
3. **The Harness switch** does not gate the CLI agents' snapshots or rewrites (it is Pi Durable's harness).
4. **pi's flags name every root**, existing or not (above).

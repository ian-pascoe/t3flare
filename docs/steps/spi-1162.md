# SPI-1162: Model endpoints with API keys, for the Durable agent

The tracer bullet of Model endpoints (draft [ADR-0034](../adr/0034-model-endpoints-are-the-owners-set-in-the-harness-panel.md)).
The owner adds, edits and removes **Model endpoints** in the Harness panel. Sessions build one pi-ai provider per
endpoint, and the Pi Durable picker lists every endpoint's models as `<endpointId>/<modelId>`, grouped by endpoint. The
Model proxy keeps working beside them until the hard cut (SPI-1176).

## Seams tested

- **The sealing module** (`test/sealed.test.ts`): it opens what it sealed, and keeps no plaintext. The mark gives the
  fingerprint. A missing or short key refuses to store. Another key, or a record moved to another name, opens nothing.
- **The endpoint store** (`test/endpointStore.test.ts`): it has its own revision and leaves the Harness and Environment
  revisions alone. pi-ai's metadata is filled in, and the owner's fields win. The key is sealed and write-only. An edit
  without a key keeps it, and a new key replaces it. The store refuses an API-key endpoint without a key, and any key
  without a credentials key. Switching to no auth drops the key; so does removing the endpoint. It refuses a reserved
  id, a credential header and plain http.
- **Model lists** (`test/endpointDiscover.test.ts`): each API's shape and way of sending the key. A failure is reported
  as its status, never its body.
- **Panel routes and page** (`test/endpointsPanel.test.ts`): save and remove are audited with the key's mark and the
  header names only. The list never shows a key. Discovery reads with the typed key, else the saved one. CSRF, Origin
  and JSON are refused as on the panel's other routes. The script path needs no CSRF token. The page escapes its strings.
- **Session models** (`apps/agents/test/endpointModels.test.ts`): one provider per endpoint under its id, with the
  stored metadata. The key is resolved at use time. A missing key fails with a clear message.
- **The picker** (`test/endpointsPicker.test.ts`): slugs are grouped by endpoint after the proxy's vendors, and
  reasoning models get the thinking picker. A label that collides with a proxy vendor is told apart by the endpoint's
  id. With no endpoints, the picker is unchanged.
- **The removed-model message** (`test/differ.test.ts`).

[`spi-1162/p1162.json`](spi-1162/p1162.json) comes from `scripts/p1162.ts`, run through `stage.ts`. Every check passed
(`"ok": true`). Every answer it keeps was scanned for the keys, and so was the evidence folder afterwards: none found.

- **Endpoints saved through the panel's API:**
  - `commissary`: Anthropic Messages at `MODEL_PROXY_URL`;
  - `openai`: OpenAI Responses at `<MODEL_PROXY_URL>/v1`.
  - Both use the proxy key, sealed. Both model lists were read: 122 models each.
- **The picker** shows `commissary/claude-haiku-5-5` under **Commissary** (with thinking) and `openai/gemini-3-flash`
  under **OpenAI (Responses)**, beside the proxy's 122. Screenshot:
  [`spi-1162/picker-grouped.png`](spi-1162/picker-grouped.png). It shows Claude Haiku 5.5 under Anthropic (the proxy),
  Commissary and OpenAI (Responses).
- **A Durable turn with tools on each:** an approval-required thread on the fixture repo edits `src/greeting.txt` and
  runs `bash test.sh` (exit 0), with both approvals accepted. Both the Anthropic Messages endpoint and the OpenAI
  Responses endpoint completed it.
- **A changed model list:** adding `claude-haiku-5-5` to `openai` put `openai/claude-haiku-5-5` in the picker at once.
  The running thread's next turn on it completed.
- **A removed endpoint:** its models left the picker, and the thread's next turn failed with: "The selected model is
  not available: its Model endpoint was removed or no longer lists it. Pick another model."
- **The audit log** has every change under `endpoints`, with no key in it.

The stage is destroyed.

## Escalations (provisional decisions; I went on with my recommendation)

1. **No OpenAI API key was available.** `~/.config/t3flare/dev.env` has no `OPENAI_API_KEY` (checked for presence only).
   - The OpenAI-API endpoint is therefore Commissary's OpenAI **Responses** API at `<MODEL_PROXY_URL>/v1`, with the
     proxy key as a bearer. This exercises pi-ai's `openai-responses` path, the bearer key and the model list from the
     OpenAI-shaped `/models`.
   - Commissary has no GPT model this key may use: `gpt-5.4-mini` answers 503 "no auth available", and `gpt-5` and
     `gpt-5.1-codex-mini` answer 403 "Model access is disabled". So the turn ran `gemini-3-flash`, which Commissary
     translates.
   - `scripts/p1162.ts` uses OpenAI's own API with `gpt-5-mini` when `OPENAI_API_KEY` is set. Recommendation: if a
     real OpenAI key matters before merge, the owner adds `OPENAI_API_KEY` to `dev.env` and I re-run on `p1162`.
2. **The credentials key comes from alchemy, not `stage.ts`.** `alchemy.run.ts` makes it with `Alchemy.Random`: 256
   bits, made once per stage and kept in the stage's Cloudflare-hosted alchemy state, which CI and the laptop share.
   - prod gets one at its next deploy, with **no owner action**: no GitHub secret and no `ci:setup` run.
   - With `stage.ts` generating it into `.alchemy/stages/<stage>.env.json`, CI's prod deploy would need a new GitHub
     secret, because CI has no such file.
   - The cost: if a stage's alchemy state were lost, its key would change and the owner would enter the endpoint keys
     again. That is the same as losing the env file.
   - This departs from the AC's wording ("that `stage.ts` generates"), not its intent.
3. **Patch 0006 to t3's `ProviderRegistry`.** Stock t3 keeps, and persists, every model a driver other than
   Codex/OpenCode/Antigravity stops listing (`shouldRetainMissingProviderModels`). Without the patch, a removed
   endpoint's models stay in the picker for good. The p1162 run saw this before the patch.
   - The patch is one line: `piDurable` retains nothing. It applies in memory at bundle time; U66 records it.
   - Alternatives were a Shadow of the whole registry, or marking the models `isCustom`, which changes the settings UI
     and how t3 picks the default model. Recommendation: keep the Patch.
4. **`pnpm run relock` fails on `main` as it stands.** The install is pinned to `unenv` rc.24 while the seeded lock
   resolves rc.25 (`ERR_PNPM_PEER_DEP_ISSUES`), and the seed also drifts `tldts` and `fast-xml-parser`.
   - I added `@earendil-works/pi-ai` (already in the lock, for `apps/agents`) to `packages/models` by hand instead. The
     lock diff is 4 lines: the importer's entry, with the version string the install wrote.
   - `pnpm install --frozen-lockfile` and `scripts/verify-lock.ts` pass.
   - Recommendation: accept the hand edit, and file the relock breakage separately.
5. **Reserved endpoint ids:** `anthropic` (the proxy's `anthropic/<id>` until the hard cut) and `default`. The
   Anthropic preset's id is `anthropic-api`.
6. **APIs offered:** Anthropic Messages, OpenAI Responses, OpenAI Completions, Google Generative AI and Mistral.
   - Codex's backend, Bedrock, Vertex and Azure need sign-ins or ambient credentials (SPI-1164 and later).
   - The recording `fetch` is passed only to the Anthropic and OpenAI APIs. pi-ai's Google and Mistral adapters may
     refuse a custom fetch.
7. **The metadata catalogs read:** anthropic, openai, google, mistral, xai, deepseek, groq and openrouter. They add
   about 0.4 MB of JSON to the Environment bundle (12.68 MiB, as before within rounding).

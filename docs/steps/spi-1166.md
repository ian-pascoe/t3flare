# SPI-1166: GitHub Copilot sign-in

Stage `p1166`, 2026-11-16. Evidence is in [`spi-1166/`](spi-1166/). It holds no token and no device code; the user code
is recorded by its shape only (`<4-4>`).

**State: built, tested against a fake GitHub, and unverified against a Copilot plan.** On `p1166` GitHub's device flow
ran from the Worker and the owner approved, but the owner's Copilot subscription had ended: GitHub refused the Copilot
token with `403 subscription_ended`, as the spike saw (SPI-1161). No Copilot token was issued, so no Copilot endpoint was
saved and no turn ran on it (see [What is unverified](#what-is-unverified)).

**Owner decision (2026-11-16, E2):** the sign-in is offered, and the terms-of-service risk of using the Copilot editor's
client outside GitHub's editors is the owner's, chosen knowingly. It is recorded in
[ADR-0018](../adr/0018-the-environment-do-is-the-credential-broker-and-each-environment-signs-in-itself.md) item 11 and
said on the panel beside the sign-in ("Your risk").

## pi-ai's flow and request shape (pi-ai 1.5.0)

The flow is pi-ai's, `dist/auth/oauth/github-copilot.js`:

- `CLIENT_ID` (:9, base64 of the Copilot editor's public GitHub client `Iv1.b507a08c87ecfe98`), `COPILOT_HEADERS`
  (:10-15: `User-Agent: GitHubCopilotChat/0.35.0`, `Editor-Version: vscode/1.107.0`,
  `Editor-Plugin-Version: copilot-chat/0.35.0`, `Copilot-Integration-Id: vscode-chat`), `COPILOT_API_VERSION` (:16,
  `2026-06-01`, on `/models` only), `getUrls` (:29-35).
- The device code (:155-196): `POST https://github.com/login/device/code`, form `client_id, scope=read:user`. The poll
  (:197-236, with `device-code.js`'s rules: wait an interval before the first poll; `slow_down` takes GitHub's `interval`,
  else 5 s more): `POST https://github.com/login/oauth/access_token`, form `client_id, device_code, grant_type`.
- The Copilot token (:237-263): `GET https://api.github.com/copilot_internal/v2/token` with the GitHub token as a bearer
  and the editor headers; `{ token, expires_at }`. The GitHub token is the refresh and never rotates.
- The base URL (:41-61): the token's `proxy-ep=proxy.<x>` as `https://api.<x>`, else
  `https://api.individual.githubcopilot.com`.
- The model list (:65-100): picker-enabled, not policy-disabled, tool-calling models; on an individual account showing
  none, the policy-enabled ones. pi-ai's login also switches "unconfigured" models' policies on.
- No revocation (GitHub revokes an app's token only with its client secret).

The request shape, `dist/api/openai-responses.js`: for `model.provider === "github-copilot"`, the dynamic headers
(:210-217, `buildCopilotDynamicHeaders`: `X-Initiator: user|agent`, `Openai-Intent: conversation-edits`,
`Copilot-Vision-Request` with an image) and no thinking-off `reasoning` (:297). The editor headers are on every model of
pi-ai's Copilot catalog.

## Seams tested

- **pi-ai's pins** (`apps/agents/test/copilotSignInShape.test.ts`):
  - pi-ai's own `login()` and `refresh()` against a stand-in fetch use exactly `copilotOAuth.ts`'s client, URLs, scope,
    form bodies and headers, the Copilot token request and the model list's headers;
  - pi-ai's `toAuth` base URL equals `copilotBaseUrl` for four tokens; ours refuses a host outside `githubcopilot.com`;
  - every model of pi-ai's Copilot catalog carries `COPILOT_HEADERS`;
  - **a request on a Copilot sign-in endpoint equals pi-ai's own `github-copilot` provider's** for the same model,
    token and context: URL, every header and body, with thinking off and on, from the owner and after a tool call, and a
    model with an "off" effort (`gpt-6-luna`). Reverting the dynamic headers or the reasoning rule fails it (checked);
  - `X-Initiator` is `user`, then `agent` after a tool call;
  - an endpoint of another kind takes no base URL or headers from a credential;
  - in a Session: the token is kept with its base URL, a renewed token's host is taken, a 401 drops it, and nothing is
    stored.
- **The vendor** (`copilotSignIn.test.ts`, against `fixtures/fakeGitHubCopilot.ts`, which checks the client, scope,
  grant type, bearer and editor headers):
  - the device page and code; a page not on github.com and a refused start are fixed texts;
  - no poll before the interval; waiting with the next poll's time; `slow_down` to GitHub's interval, else 5 s more;
  - approval: the Copilot token as access, the GitHub token as refresh, the real expiry; the request bounded and not
    following redirects;
  - declined, lapsed (at GitHub, and here without asking) and unreachable;
  - a 403 `subscription_ended` at sign-in: refused with "needs a Copilot plan" and where to revoke, without the body;
  - a token naming a foreign host is not used; `use` gives the token's base URL and the editor headers;
  - renewal keeps the GitHub token; a 400, 401 or 403 with an error object ends it, a rate limit (`retry-after`,
    `x-ratelimit-remaining: 0`), an edge page, a bare JSON value, a 404, a 503 or no network does not;
  - `revoke` sends nothing.
- **The broker with Copilot** (`copilotBroker.test.ts`; each ends with a scan of storage and console for every token,
  device code and user code):
  - waiting sealed, GitHub not asked before the interval, the next poll's time sealed across asks; `slow_down` across
    asks; signed in with the token's base URL in the status;
  - access gives the Copilot token, its base URL and the editor headers, never the GitHub token;
  - five callers near expiry cause one Copilot token request; the GitHub token stays the grant;
  - a 401 with GitHub's error object signs out once; a rate limit keeps a valid token and shows the problem until a
    renewal succeeds; an expired token with an edge page is retryable;
  - sign-out: tokens removed, then the Sessions' step, nothing sent to GitHub;
  - a sign-out overtaking the Copilot token exchange wins; a newer start replaces a waiting attempt (the older one's
    approval is not taken); a declined attempt ends.
- **The panel** (`endpointsSignIn.test.ts`, the real routes, store and broker):
  - the device form, its note and no paste field;
  - start, a waiting ask, approval, then a `copilot` endpoint saved with **its stand-in base URL and no headers**, the
    list read at the token's base URL with the bearer, editor headers and API version; only start and end audited;
    nothing secret on the page, in the answers, audit, storage or console, also while waiting;
  - a Session gets the token with the token's base URL and the editor headers, for the endpoint's target only;
  - the list read again; a no-plan refusal saves nothing; sign-out's `revocation`; the target kept (no headers, no other
    base URL).
- **The model list** (`endpointDiscover.test.ts`): Copilot's catalog by pi-ai's rules and the endpoint's API; the

- **The catalog** (`endpointStore.test.ts`): Copilot's metadata and compat first for its host; never for another.

## What is unverified

The ticket's criterion "sign-in, a Durable turn with tools, and sign-out on a throwaway stage" **is met for the device
flow and sign-out only**; the turn needs a Copilot plan the owner's account no longer has. The fake-vendor tests, the
wire pin against pi-ai's own provider, and the API-key control turn stand in for it. Unverified against GitHub:

- **A Copilot token issued to a Worker**, its `proxy-ep` host, its renewal, and the model list's real fields.
- **A Responses request to Copilot's API from a Worker's egress** with this shape (pinned only against pi-ai's).
- **What GitHub answers for a revoked GitHub token**, and Copilot's own usage-limit errors in a turn (no SPI-1172 row
  added; E5).

The criterion "Copilot's per-credential base URL and required headers are applied by the broker, not stored in endpoint
config" is met and tested (`endpointsSignIn.test.ts`, `copilotBroker.test.ts`, `copilotSignInShape.test.ts`).

## Escalations

All decided by the orchestrator or the owner, 2026-11-16:

- **E1 One API per endpoint (kept; the orchestrator files a follow-up).** The Copilot endpoint speaks Copilot's
  Responses API (GPT, Grok, mai); Copilot's Claude (Messages) and Gemini/Kimi (Chat Completions) models are not listed.
- **E2 The terms-of-service risk is the owner's (owner).** The panel's "Your risk" note stays as written; ADR-0018 item
  11 records it.
- **E3 No model policy switched on (accepted).** pi-ai's login enables "unconfigured" models for the account; ours
  changes no account setting, and lists such models as pi-ai does.
- **E4 github.com only (accepted).** No GitHub Enterprise domain.
- **E5 No Copilot rows in SPI-1172's failure table (accepted).** No documented fixtures; a 401 or 403 is the generic
  `sign_in_refused`.

### 🌳 Decisions

- **D1** Copilot is one `SIGN_IN_KINDS` row and one vendor; the broker, lock, sign-out order, panel route and the
  Session's token handling are shared. What a third vendor needed was added generally: `SignInVendor.use` (where a
  token's requests go and its headers), a start's `device`, a completion's `waiting`, `SignInKind.device` and
  `baseUrlFromCredential`, `EndpointCredential.baseUrl`/`headers`.
- **D2** The device flow is polled by the panel's asks (each at most one request to GitHub, never before its interval),
  not by an alarm or a loop: nothing runs when no one is waiting, and a reload keeps "Check sign-in".
- **D3** The stored endpoint's base URL is a fixed stand-in (`https://api.individual.githubcopilot.com`) for the target
  rule; the Session uses the broker's only for a kind that says so.
- **D4** Refusal at renewal: SPI-1165's rule (400, 401 or 403 with an error object), GitHub's `{ message }` counting,
  less GitHub's rate limits. A `subscription_ended` 403 therefore signs out.
- **D5** Revocation: none; sign-out deletes here and says where to revoke.
- **D6** Fragility U82.

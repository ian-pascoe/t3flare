# SPI-1167: The model relay, with Codex as its first CLI

CLI agents reach Model endpoints through a **model relay**: `http://computer.internal/t3flare/model/<endpointId>/…` in
the Container, with a per-process model handle. The Workers check the handle, swap in the endpoint's own credential
(the endpoint store's `resolve`) and stream the request to the endpoint unchanged. Codex is the first CLI on it.
Decision record: [ADR-0016](../adr/0016-no-vendor-credential-enters-a-container-and-cli-agents-reach-the-model-proxy.md)'s
model relay refinement; [ADR-0034](../adr/0034-model-endpoints-are-the-owners-set-in-the-harness-panel.md) item 7.

## Seams tested

- **The relay route** (`apps/agents/test/modelRelayRoute.test.ts`): the request goes to the base URL with the
  endpoint's headers and key; only the allowlist of the Container's headers goes on (routing headers such as
  `x-portkey-custom-host`, `x-forwarded-host`, `host`, `forwarded`, `user-agent`, Codex's own, and every key header and
  cookie are dropped; an Anthropic endpoint takes `anthropic-version`/`anthropic-beta`, not `openai-beta`); no cookie or
  hop-by-hop header comes back; the answer streams with idle gaps; the handle is taken from `x-api-key` too and never
  forwarded; no handle is refused before anyone is asked; a refusal passes on; an encoded dot segment, `/` or `\`
  (doubly encoded too) is 400 before anyone is asked; a dot segment `URL` resolves names another endpoint, which the
  handle's scope refuses; a path without an endpoint is 404; a Workspace that does not answer is 502, logged with the
  endpoint; a redirect is 502 and not passed on; an unreachable endpoint is 502 without its error's text; an endpoint's
  own error passes through; every request is logged with endpoint, status and handle id, never a handle or a key.
- **The Workspace DO's check** (`modelRelayRoute.test.ts`, `authorizeModelRelay`): a live handle gets its configured
  endpoint and the key is remembered; an unknown or revoked handle is 401, another endpoint 403, a deleted Workspace
  410, asking no one; the Environment's refusal passes on; a keyless endpoint remembers nothing.
- **The endpoint keys** (`apps/agents/test/endpointKeys.test.ts`, `apps/environment/test/endpointLeak.test.ts`): one
  pattern per endpoint, the newest, capped, never a value; no short key hash-scanned; the leak check's values and

- **The handle registry** (`apps/agents/test/processHost.test.ts`): a handle in the process's environment only, never
  its argv, resolving with its endpoints until the process exits; one per process; none for a process that names no
  endpoint; not a Tool handle and not taken from the profile's environment.
- **The model list follows the endpoints** (`apps/environment/test/endpointsChanged.test.ts`): each change runs the
  driver's refresh while its scope is open, none after.
- **The Environment's target** (`apps/environment/test/endpointRelay.test.ts`): base URL and headers with the key in
  the header each API takes; none for no auth; 404 for a gone endpoint, 503 for a key that no longer opens, naming no key.
- **Codex** (`cliProfiles.test.ts`, `codexGuard.test.ts`, `codexEndpoints.test.ts`, `variableNames.test.ts`): the
  providers' TOML, `modelRelay`, the handle excluded from shells, the process provider from the session's model, the

## Escalations (provisional, as assumed)

1. **A turn on another provider's model in a Codex thread is refused** (another endpoint, or the Model proxy). Codex
   runs a thread's turns only on its process's provider ("This chat uses <a>, but your current provider is <b>"), and
   t3 resumes the thread in the running process on a model change: it never asks the adapter's
   `planSelectionTransition`, so a session restart could not be planned from the driver (tried on stage, then removed).
   t3 shows its generic "The provider could not start this turn"; the guard's reason ("start a new thread for this
   model") is in the cause only. Recommendation: accept; a cross-provider switch needs a new thread. A Shadow or Patch
   of t3's turn start could restart the process, if the owner wants the switch.
2. **The handle is made by the Workspace DO**, not the Environment (unlike the Tool handle), and only for a process
   whose profile asks: it never leaves the Workspace DO and the process. Claude Code, OpenCode and pi ask in their own
   tickets.
3. **Codex's provider id is `t3flare-endpoint-<endpointId>`**, prefixed so no endpoint id can take a Codex built-in id
   (`openai`, `ollama`, …).
4. **The "handle id" in the log is the key of the process the handle was issued to** (`proc-…`); a handle that names
   no live process logs `null`.
5. **The relay follows no redirect** (502 naming the status) and drops `set-cookie` and hop-by-hop headers from the
   answer.
6. **The Codex turn ran `claude-haiku-5-5`** through Commissary's Responses API: `gemini-3-flash` (SPI-1162's) is now
   "deprecated" there (410), and its GPT models are not enabled for this key (403). If a real OpenAI key matters, the
   owner adds `OPENAI_API_KEY` to `dev.env` and the script uses OpenAI's API.
7. **An endpoint added while a Codex process runs** is in that process's config only from its next process (a new
   thread or session). Removed ones answer 404 at the relay.
8. **Codex's investigating text generation** (`codex exec`, t3's review guide) still uses the Model proxy only; text
   generation on endpoints is SPI-1163.
9. **`T3FLARE_PROBE=1`** on the stage also points its Usage page at the probe's Commissary stand-in (parity batch 2's
   design); harmless on a throwaway stage.
10. A small diagnostic stays: a Codex `turn/start` that Codex refuses is logged (`codex-turn-start-failed`), as t3
    shows only a generic failure.

   `anthropic-version`/`anthropic-beta` (Anthropic). `accept-encoding` is not forwarded: workerd negotiates and decodes

3. **`docs/upstream-fragility.md` U69** (Where, Breaks when, Detection with its silent paths, Blast radius, Fix),
   linked from U29 and from the bump table's check and Docker rows.
4. **Glossary**: **Model relay** and **Handle** keep the concepts; the mechanism is in ADR-0016's refinement.
5. **Tests that fail when reverted**: the response's cookie and hop-by-hop drop; the request headers (the allowlist);
   `authorizeModelRelay` (extracted from `WorkspaceDO.modelRelay`); `EndpointKeyPatterns` and `leakTargets` (from
   `#rememberEndpointKey` and `leakCheck`); `endpointLeakCredentials` (from the admin route); `refreshOnEndpointsChanged`
   (the listener both drivers now use), and on the stage the list following a change without a refresh.
   `upstreamUrl`'s unreachable branch is gone: the path checks come first.
6. **Logging**: an invalid path logs its endpoint (null when the path names none) with a null handle; a Workspace that
   does not answer is caught inside the route (502, the endpoint logged); `model-relay-failed` logs the endpoint the

7. **Leak guard**: keys under 20 characters (`MIN_SCANNED_KEY_LENGTH`) are looked for only in the DO's files, never by

8. **Path**: a segment that decodes (up to three times) to `.` or `..`, or holds `/` or `\`, is refused with 400.
   `URL` already resolves literal and singly encoded dot segments before the route sees the path; such a path names

9. **Scope**: the handle is good only for the endpoints its profile names (`modelRelay: [ids]`; Codex's Responses
   endpoints at its spawn); others get 403, on the stage too. An endpoint that does not exist gets 403 as well: the
   scope is checked before the endpoint is looked up.
10. **The shell check** is in the stage evidence (above).
11. **Constant-time compare**: `sameHandle`, for both handles.
12. **Standards**: `newHandle`/`HANDLE`/`sameHandle` shared by both handles; `parseEndpointSlug` used by the guard and
    the profile; `endpointsOfApi` for the Responses endpoints (Codex's list, routing and spawn); `RelayedEndpoint`;
    `ToolCaller` is `HandleCaller`; the key headers come from `credentialHeaderOf` (`KEY_HEADERS`, discovery too).
13. **Follow-up for SPI-1168/1171**: pi-ai sends an `sk-ant-oat…` key (a Claude Code OAuth token) as a Bearer, while the
    relay puts an Anthropic Messages key in `x-api-key`. A sign-in's token needs its own header rule
    (`credentialHeaderOf` by credential kind, not only API) before Claude Code or a Claude sign-in uses the relay.

Rejected for now: salting the scan per run (the scanner takes a prefix, a length and a hash; a per-scan salt would
change `leakscan.ts`'s protocol for every credential). The minimum length removes the reversible case.


## Review round 2

No stage run this round (unit tests and the reviewer's probe, `/tmp/mep/r2probe/probe.mts`).

1. **A malformed escape no longer bypasses the path check.** `decodedSegment` now refuses (400) a segment whose decode
   throws (`%ff`, an overlong `%c0%ae`), or that has not settled after `MAX_DECODES` (3) decodes (`%2525252e`); a
   segment that settles is refused if it is `.` or `..`, alone or followed by `;` (Tomcat's `..;`), or holds `/`, `\`
   or a control character (a NUL a server may cut at, a tab, a CR or LF). The "in any encoding" test has the
   reviewer's three bypasses, the 3- and 4-level encodings, `..;`, `.;`, `%2e%2e;x=1`, NUL, tab and CR LF; another test
   checks an ordinary escape (`%3A`, `%20`) still passes. The probe now answers 400 for every bypass and malformed or
   deep encoding. Cost: a path holding a literal `%` (`%25`) is refused too, as its second decode fails; no model API
   path holds one.
2. **ADR-0016's residual** says the allowlist covers headers only: body and query pass unchanged by design, so a gateway
   that routes on a body or query field (LiteLLM's `api_base`) is outside what the relay protects.
3. **A skipped key is named.** `leakTargets` returns `skipped` (a key under 20 characters: not hash-scanned in the
   Container; under 8: not searched at all), and `leakCheck`'s answer carries it as `notScanned`, by the credential's
   name (`endpoint:<id>`), never its value. Tested.
4. **The MCP relay's bearer** uses `HANDLE` from `@t3flare/workspace-client`.
5. **U69** has the "Breaks when" line for a CLI that starts requiring a header the allowlist drops; the relay log's
   `dropped` field names it.
6. **`MIN_SEARCHED_VALUE_LENGTH`** (8) names the bare number.
7. **ADR-0034**: the relay is item 7.
8. **Smells**: `relayedEndpoint` is gone (a `ModelEndpoint` is a `RelayedEndpoint`; the narrow type stays for the
   profiles); `authorizeModelRelay`'s caller is a `HandleCaller` with its endpoints.

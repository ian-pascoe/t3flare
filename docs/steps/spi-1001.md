## What was built

### Discovery (`packages/skills`, new; `WorkspaceDO.skills` and `prompts`)

- `@t3flare/skills` holds discovery, Prompt templates and the listing as plain functions over a small `SkillFiles`
  reader, so the Workspace DO, the Session and the Environment all load it. Ported from cloudpid@47941c7c
  (`skills-discovery.ts`, `prompt-templates.ts`, `skills.ts`), with the ticket's roots and rules. `yaml` is a
  `catalog:` dependency, added through the relock.
- **Skills.** `.pi/skills`, then `.agents/skills`, then `.claude/skills`, in each directory from the thread's cwd up to
  the repo root (`/workspace/repo`), nearest directory first; the first name found wins. Dot directories,
  `node_modules` and the inside of another skill are not descended; a link to a directory is followed one level, as pi
  does.
- **The rules table**, the same for the agent and the composer: no frontmatter, not YAML or no `description`: skipped;
  no `name`: the folder's; a name t3 cannot mention (over 64 characters, or outside `[a-zA-Z0-9:_-]` with at least one
  letter): skipped; description cut to 1,024; `allowed-tools` ignored; at most 100 Repo skills, nearest first.
- **The answer** is `{ skills, skipped: [{ path, reason }], omitted }`. A same-named skill that loses is in `skipped`
  ("is shadowed by …"), and so is each skill a rule drops. `omitted` counts the `SKILL.md` files past the cap, unread.
- **The Environment skill set** is a parameter, first in the list and beating a Repo skill of the same name; the
  Workspace DO passes `#environmentSkills()`, empty until SPI-1148.
- **Prompt templates.** The `.md` files directly in the cwd's `.pi/prompts`: no `.agents/prompts`, no
  `.claude/commands`. `description` (or the body's first line, cut to 60), `argument-hint`.
- **The Workspace DO** (`apps/agents/src/workspace/skills.ts`) runs both on `WorkspaceEnvHost.readEnv`: its own files,
  hidden names listed, git's ignore rules off. It never reaches the Container. When anything is skipped it logs one
  `{"t3flare":"skills",…}` line (the first 20 skipped, and their count).

### The Session (`apps/agents/src/extensions/skills.ts`)

- The `skills` extension, registered in `packages/harness-registry` (on by default) and installed in `SessionDO`'s
  `#installHarness` as the other switchable extensions are.
- Its section is pi's `<available_skills>` (name, description, `SKILL.md` path) in a `<skills>` block, without the
  `disable-model-invocation` skills, ending with one line when the cap left skills out. It is a `frozenSection`: read
  once per context window. An empty list freezes as empty; a read that fails is logged and freezes nothing, so the
  request still goes.
- `ComputerExecutionEnv.discoverSkills` (computer-env) now answers the discovery's whole shape (`WireSkillDiscovery`).

### The composer snapshot (`apps/environment/src/provider/skills.ts`, `driver.ts`)

- `snapshotForCwd` on the Pi Durable instance: the machine snapshot plus the Workspace's skills (scope `project`,
  `/w/<id>/…` paths, `userInvocationOnly` from `disable-model-invocation`) and its Prompt templates as `slashCommands`
  (the hint as `input.hint`). Freshness is t3's TTL.
- Empty for a path that is no Workspace, and with the switch off (`EnvironmentServices.skillsEnabled`, read from the
  stored harness settings at each call). A Workspace that does not answer fails the scan with a `ProviderDriverError`,
  as stock scans fail.

### Expansion (`turnPrompt`, `provider/attachments.ts`)

- `turnPrompt` takes an optional `skills` (amendment): the Pi Durable adapter passes the thread's
  (`messageSkillsFor(cwd, …)`) for a new turn and for a steer; the ACP builder (`acpDriver.ts`) passes none, so Claude
  and OpenCode threads get the message as typed. SPI-1151 switches it on for OpenCode.
- A message that holds a currency sigil or starts with `/` asks the Workspace afresh; a plain one costs nothing.
- `$name` (t3's `matchInlineSkills`, with code spans and fenced blocks blanked first) appends a
  `<skill name location>` block, t3's Pi provider's, once per skill. A leading `/skill:name args` becomes the block and
  its arguments; a leading `/template args` the template with pi's substitution. An unknown name is left as typed.
- Blocks use the Workspace's inner paths (`/workspace/repo/…`) and share the message's text budget (120,000 less the
  attachments' notes); a body that does not fit is named in a bracketed note, not embedded. Attachments get what is
  left. The Session stores the expanded text; t3's transcript keeps what was typed.

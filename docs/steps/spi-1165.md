# SPI-1165: Claude subscription sign-in (Claude Code OAuth)

Stage `p1165`, 2026-11-16. Evidence is in [`spi-1165/`](spi-1165/). It holds no token, no code and no verifier. The
pasted code is recorded by its parts' lengths; the authorize URL's state and challenge by length. The owner's email and
Anthropic account id are redacted to `<owner email>` and `<account uuid>`.

**State: built, tested against a fake Anthropic, and verified on the stage with the owner's Claude plan.** The sign-in,
a Durable turn with tools on `claude/claude-haiku-5-5`, and a sign-out all ran on `p1165`.

**Owner decision (2026-11-13):** the sign-in is offered, and the terms-of-service risk of using Claude Code's OAuth
client outside Claude Code is the owner's, chosen knowingly. It is recorded in
[ADR-0018](../adr/0018-the-environment-do-is-the-credential-broker-and-each-environment-signs-in-itself.md) item 10 and
said on the panel beside the sign-in ("Your risk").

## pi-ai's flow and request shape (pi-ai 1.5.0)

The flow is pi-ai's copy-code flow, `dist/auth/oauth/anthropic.js`:

- `CLIENT_ID` (:11, base64 of Claude Code's public client id), `AUTHORIZE_URL` `https://claude.ai/oauth/authorize`
  (:12), `TOKEN_URL` `https://platform.claude.com/v1/oauth/token` (:13), `COPY_CODE_REDIRECT_URI`
  `https://platform.claude.com/oauth/code/callback` (:20), `SCOPES` (:23).
- `loginAnthropicCopyCode` (:172-202): the authorize parameters `code=true, client_id, response_type, redirect_uri,
  scope, code_challenge, code_challenge_method=S256, state` with **the verifier as the state**; the paste parsed as
  `code#state`, a URL, or `code=…`; the state checked only when present.
- The exchange (:85-113): JSON `{grant_type, client_id, code, state, redirect_uri, code_verifier}`. The refresh
  (:206-231): JSON `{grant_type: "refresh_token", client_id, refresh_token}`. pi-ai stores `expires` 5 minutes short.
- No revocation.

The request shape for an OAuth token, `dist/api/anthropic-messages.js`:

- `isOAuthToken` (:767): the key holds `sk-ant-oat`.
- `createClient` (:786-801): Bearer auth (`authToken`), with `accept: application/json`,
  `anthropic-dangerous-direct-browser-access: true`, `user-agent: claude-cli/2.1.280` (`claudeCodeVersion`, :45) and
  `x-app: cli`.
- `getBetaFeatures` (:858-859): `claude-code-20250219, oauth-2025-04-20` first.
- `buildParams` (:911-926): the system's first block is "You are Claude Code, Anthropic's official CLI for Claude.",
  the Session's system prompt the second.
- Tools named in Claude Code's casing (`toClaudeCodeName`, :70; `bash` goes as `Bash`) and mapped back on return.
- The request goes to `/v1/messages?beta=true`.

## Escalations

### 👀 Worth a glance (provisional, built)

- **E1 A state of its own, not the verifier.** pi-ai sends the PKCE verifier as the state, which puts it in the
  browser's address and on Anthropic's page beside the code. Ours is random; Anthropic accepted it on the stage. ➡️ Keep.
- **E2 An API-key endpoint refuses an `sk-ant-oat` key.** pi-ai gives any such key Claude Code's request shape, so this
  keeps that shape to Claude sign-in endpoints, and keeps a subscription's token from being copied in as a key
  (ADR-0018). ➡️ Keep.
- **E3 A Claude sign-in's token must hold `sk-ant-oat`**, or the sign-in is refused (the requests would otherwise go as
  an API key's and fail). ➡️ Keep; U81 names it.

### 🌳 Decisions

- **D1** The broker, lock, sign-out order, panel route and the Session's token handling are 1164's, unchanged; Claude is
  one `SIGN_IN_KINDS` row, one vendor, and one empty `SIGN_IN_REQUESTS` entry.
- **D2** No request rules of ours for Claude: pi-ai applies the shape from the token. The test pins it, so a pi-ai bump
  that changes it fails the check.
- **D3** Revocation: none. Sign-out deletes the tokens here, stops the Sessions, sends Anthropic nothing and answers
  `revoked: false` with where to remove the grant; the note, Sign out's confirmation and removal's answer say it too.
- **D4** A sign-in's model list goes with the token in the headers its kind needs (`signInHeaders`); for ChatGPT that is
  the same bearer as before.
- **D5** The paste is required to carry its state (pi-ai accepts a bare code).
- **D6** Refresh-ending codes: `invalid_grant`, `invalid_client`, `unauthorized_client`; anything else is a passing
  failure.
- **D7** Fragility U81 (U78 to U80 landed on main meanwhile).

# SPI-1165: Claude subscription sign-in (Claude Code OAuth)

Stage `p1165`, 2026-11-16. Evidence is in [`spi-1165/`](spi-1165/). It holds no token, no code and no verifier. The
pasted code is recorded by its parts' lengths; the authorize URL's state and challenge by length. The owner's email and
Anthropic account id are redacted to `<owner email>` and `<account uuid>`.

**State: built, tested against a fake Anthropic, and verified on the stage with the owner's Claude plan.** The sign-in,
a Durable turn with tools on `claude/claude-haiku-5-5`, and a sign-out all ran on `p1165`.

**Owner decision (2026-11-13):** the sign-in is offered, and the terms-of-service risk of using Claude Code's OAuth
client outside Claude Code is the owner's, chosen knowingly. It is recorded in
[ADR-0018](../adr/0018-the-environment-do-is-the-credential-broker-and-each-environment-signs-in-itself.md) item 10 and
said on the panel beside the sign-in ("Your risk").

## pi-ai's flow and request shape (pi-ai 1.5.0)

The flow is pi-ai's copy-code flow, `dist/auth/oauth/anthropic.js`:

- `CLIENT_ID` (:11, base64 of Claude Code's public client id), `AUTHORIZE_URL` `https://claude.ai/oauth/authorize`
  (:12), `TOKEN_URL` `https://platform.claude.com/v1/oauth/token` (:13), `COPY_CODE_REDIRECT_URI`
  `https://platform.claude.com/oauth/code/callback` (:20), `SCOPES` (:23).
- `loginAnthropicCopyCode` (:172-202): the authorize parameters `code=true, client_id, response_type, redirect_uri,
  scope, code_challenge, code_challenge_method=S256, state` with **the verifier as the state**; the paste parsed as
  `code#state`, a URL, or `code=…`; the state checked only when present.
- The exchange (:85-113): JSON `{grant_type, client_id, code, state, redirect_uri, code_verifier}`. The refresh
  (:206-231): JSON `{grant_type: "refresh_token", client_id, refresh_token}`. pi-ai stores `expires` 5 minutes short.
- No revocation.

The request shape for an OAuth token, `dist/api/anthropic-messages.js`:

- `isOAuthToken` (:767): the key holds `sk-ant-oat`.
- `createClient` (:786-801): Bearer auth (`authToken`), with `accept: application/json`,
  `anthropic-dangerous-direct-browser-access: true`, `user-agent: claude-cli/2.1.280` (`claudeCodeVersion`, :45) and
  `x-app: cli`.
- `getBetaFeatures` (:858-859): `claude-code-20250219, oauth-2025-04-20` first.
- `buildParams` (:911-926): the system's first block is "You are Claude Code, Anthropic's official CLI for Claude.",
  the Session's system prompt the second.
- Tools named in Claude Code's casing (`toClaudeCodeName`, :70; `bash` goes as `Bash`) and mapped back on return.
- The request goes to `/v1/messages?beta=true`.

## What is not verified

- **A refresh at Anthropic** through the broker: the token lasts 8 h, longer than the stage run. The rotation and its
  refusal are as the spike saw them (SPI-1161 Q5) and tested against the fake.
- **Whether Anthropic ends the replaced access token at a refresh.** A Session keeps a token at most 5 minutes and
  never past 2 minutes before its expiry, and the broker renews with less than 5 minutes left, so a Session may send
  the replaced token for at most 3 minutes after a renewal. If Anthropic refuses it, that request's 401 is
  `sign_in_refused` (not retried), the Session drops the token, and the next turn takes the renewed one (U81).
- **A 401 on a revoked grant mid-turn**, and how Anthropic's disguised refusal (429 `rate_limit_error`) reads in a turn:
  classified by SPI-1172's tables, not here.

## Escalations

### 👀 Worth a glance (provisional, built)

- **E1 A state of its own, not the verifier.** pi-ai sends the PKCE verifier as the state, which puts it in the
  browser's address and on Anthropic's page beside the code. Ours is random; Anthropic accepted it on the stage. ➡️ Keep.
- **E2 An API-key endpoint refuses an `sk-ant-oat` key.** pi-ai gives any such key Claude Code's request shape, so this
  keeps that shape to Claude sign-in endpoints, and keeps a subscription's token from being copied in as a key
  (ADR-0018). ➡️ Keep.
- **E3 A Claude sign-in's token must hold `sk-ant-oat`**, or the sign-in is refused (the requests would otherwise go as
  an API key's and fail). ➡️ Keep; U81 names it.

### 🌳 Decisions

- **D1** The broker, lock, sign-out order, panel route and the Session's token handling are 1164's, unchanged; Claude is
  one `SIGN_IN_KINDS` row and one vendor, with no `SIGN_IN_REQUESTS` entry. The broker's one change is which account
  fields a sign-out keeps (`keepsEmail`).
- **D2** No request rules of ours for Claude: pi-ai applies the shape from the token. The test pins it, so a pi-ai bump
  that changes it fails the check.
- **D3** Revocation: none. Sign-out deletes the tokens here, stops the Sessions, sends Anthropic nothing and answers
  `revoked: false` with where to remove the grant; the note, Sign out's confirmation and removal's answer say it too.
- **D4** A sign-in's model list goes with the token in the headers its kind needs (`signInHeaders`); for ChatGPT that is
  the same bearer as before.
- **D5** The paste is required to carry its state (pi-ai accepts a bare code), and an address is taken only if it is
  Anthropic's code page (review round 1).
- **D6** A refresh ends the sign-in on a 400, 401 or 403 with a JSON body (an OAuth or Anthropic API error) but
  Anthropic's passing codes (`temporarily_unavailable`, `server_error`, `slow_down`); a body that is not JSON (an edge's
  page, nothing) and other statuses are passing failures, retried (review rounds 1 and 2). The accepted cost: a JSON 400, 401 or 403 during an incident at Anthropic would sign the owner out (sign in again; the old grant stays at claude.ai), weighed against retrying a removed grant's refresh forever; what Anthropic answers for a removed grant is unverified.
- **D7** Fragility U81 (U78 to U80 landed on main meanwhile).

## Review round 1 (0 blocking)

Each fix has a test that fails with the fix reverted (checked by reverting each).

1. **The pasted address.** Only `code#state` or Anthropic's code page (`https://platform.claude.com/oauth/code/callback`,
   with or without its scheme) is taken; any other address, the authorize link itself included, is refused before an
   exchange and spends nothing. The `code=…&state=…` form is gone. Test: the authorize link, another host, another
   path, a bare query.
2. **No echo of the paste.** No answer held it (the texts are fixed), and now the state-mismatch and refused-address
   tests also scan each answer for the pasted code, its parts, the state and the verifier.
3. **A removed grant ends the sign-in.** A refresh answered 400, 401 or 403 ends it whatever the body (`http_401` when
   there is no OAuth code), but for Anthropic's passing codes; the next turn fails naming the sign-in, not "retry".
   Tests: the vendor (six cases) and the broker (a 401 with Anthropic's API error body signs out, one refresh). The
   window in which a Session may send a replaced access token is in "What is not verified" and U81.
4. **Sign-out forgets the email** of a Claude sign-in (and a refused renewal does): the broker keeps an account's email
   only with a registration the vendor issued (OpenAI's client id, whose next sign-in is hinted with it, ADR-0018 item
   6); Claude has none. Test in `claudeBroker.test.ts`; ChatGPT's keeps its email, as its test checks.
5. **The model list read again** (`/api/endpoints/discover` on the signed-in Claude endpoint): the token goes as a bearer
   with the OAuth beta, not as `x-api-key`. Test.
6. **Our token mark and pi-ai's `isOAuthToken`** are pinned together: a key built from our mark gets pi-ai's OAuth shape,
   and a key one character short of it gets none, so a looser or stricter mark fails (checked with `sk-ant-o` and
   `sk-ant-oat01`).
7. **Survivors**, each now tested: a renewal whose access token lacks the mark is not taken; `invalid_client` and
   `unauthorized_client` end it; the save-failure answer's "dropped here" and claude.ai text; `redirect: "manual"` and
   a bound on every request (the fake records both); the timeout, with the bound injectable (`timeoutMs`): a token
   endpoint that never answers gives up within it, the attempt still waiting.
8. **`credentials/oauth.ts`** holds what the vendors share: `base64url`, `random`, `pkceChallenge`, `isRecord`,
   `OAUTH_TIMEOUT_MS`, `oauthErrorCode`. Each vendor keeps its codes.
9. **`SIGN_IN_REQUESTS`** is a `Partial` record with no Claude entry; `signInProvider` adds no `onPayload` for a kind
   without rules.
10. **`scopes`, `subject` and `email`** are `SignInCredential`'s (optional); `ClaudeCredential` is gone.
11. **`SignInKind.noteTitle`** (was `caution`).
12. ADR-0018: the state's outcome stated (accepted on p1165); "the owner" for "he/his"; item 10 says a refused refresh
    signs out and a Claude sign-out forgets the account whole.
13. GLOSSARY **Subscription**: "(ChatGPT, Claude)" only.
14. This report: the turn's evidence shows the endpoint by the slug's id only (item 7 of the evidence).

No new stage run: the requests on the wire are unchanged but for refusing more pastes, which the tests pin.

## Review round 2 (0 blocking, 1 hard)

Each fix has a test that fails with it reverted (checked by reverting each).

1. **HARD**: `credentials/claude.ts`'s header says "the owner".
2. **The refresh-ending rule, narrowed**: only a 400, 401 or 403 with a JSON body ends the sign-in; an HTML page or an
   empty body is passing trouble, retried. Tests for both. The accepted cost is stated in D6, ADR-0018 item 10 and U81.
3. **The paste**: `NOT_IN_CODE` (`/[\s#?&=]/`) is pinned by a test (the right state followed by `?`, `&`, `=` or a
   second `#` is asked for again, never exchanged; with `/\s/` it fails). A code pasted in quotes (straight, curly,
   backticks) is unwrapped and completes.
4. **Survivors**: `server_error` and `slow_down` each have a case; the default bound is pinned at 15 s
   (`AbortSignal.timeout` is called with 15000).
5. `hasScheme` names the scheme test once.
6. **`SignInKind.keepsEmail`** (ChatGPT true, Claude false) replaces the broker's `clientId` inference; the broker reads
   the status once. ChatGPT's sign-out keeps its email, as its test checks (it fails with the flag false).
7. **`oauthRequestOptions`** in `credentials/oauth.ts`: the bound (and the caller's deadline) and `redirect: "manual"`,
   used by ChatGPT's requests and Claude's. ChatGPT's requests carry the same options as before. `oauthErrorOf` also
   says whether an error's body was JSON.
8. This report's "What changed" and D1; `chatgpt.ts`'s double blank line.

# SPI-1173: The Usage page from t3flare's own usage records

t3's Usage page now reads t3flare's own **usage records** (`GLOSSARY.md`): every model answer on a Model endpoint,
counted where t3flare sees it, kept by the Environment DO, and served through t3's usage readers. No vendor's
management API is read for the page. Fragility: [U79](../upstream-fragility.md#u79-the-usage-page-from-t3flares-own-usage-records-spi-1173)
(and a note on U58).

## Where a record is made

| Seam | What it reads | Where |
| -- | -- | -- |
| **Durable** | Each final assistant message of an endpoint provider's model (turns, compaction, the extensions' own calls: all go through the Session's models): pi-ai's `usage` and `cost.total`. Until the hard cut, the Model proxy's answers too, under the proxy's id `anthropic`. | `apps/agents/src/session/models.ts` (`answering`, `EndpointAccess.answered`, `proxyModels`' `answered`), `session/endpoints.ts` (`durableUsage`), `SessionDO.ts` |
| **Text generation** | Its one answer's pi-ai usage, under `text-generation` | `endpointText.ts`, `endpointTextGeneration.ts` |
| **Relay** | Each CLI request's answer as it streams past: the final stream event or the body, per API (below) | `apps/agents/src/workspace/relayUsage.ts`, wired by a `usage` dep in `modelRelay.ts` and `workspaceProxy.ts` |

Each seam sends its record to the Environment DO's new `recordUsage` RPC (never boots t3) in `ctx.waitUntil`, after
the answer; a failed send loses that record and is logged by name only. The record type is
`@t3flare/models/usage` (`UsageEntry`): agent, endpoint id, model id, time, an opaque session (a Session's id, a CLI
process's key), the token counts and the cost when known. **No key, handle, prompt or answer text**: the relay reader
keeps counts and the model's name and drops the text as it reads.

### The relay's reader

A `TransformStream` that enqueues each chunk to the CLI first, then reads a copy: an SSE stream line by line (only
`data:` lines holding `"usage` or `"model` are parsed), a JSON body whole once it has ended (Google's streamed JSON
array included). No buffering of the stream and no latency: nothing waits on the reader. Any failure in it stops the
reading, never the answer (tests: broken JSON, a refusal, a throwing record). A line or body over 4 MiB stops it.

| API | Usage taken from |
| -- | -- |
| Anthropic Messages | `message_start`'s message (model, input, cache read, cache write), the last `message_delta` (output); a body's `usage` |
| OpenAI Responses | `response.completed` (or `.incomplete`, `.failed`)'s response (`input_tokens` less `cached_tokens`, `reasoning_tokens`) |
| Chat Completions | the last chunk's `usage` (`prompt_tokens` less `cached_tokens`) |
| Google | the last `usageMetadata` (thoughts counted into output; `modelVersion`) |
| Mistral | `conversation.response.done`'s usage, or Chat Completions' shape |

The model is the request's own id when it named one to the relay (Claude Code's model-routed requests), else the
answer's; the Environment maps a dated answer name to the endpoint's listed model (`claude-x-20250929` → `claude-x`).
The agent is the process's CLI (`codex`, `claude`, `opencode`, `pi`); the stage's `probe` is not recorded.

## Storage (the Environment)

`apps/environment/src/usage/records.ts`, a table in the Environment DO's SQLite:

- **Rolled up as written**: one row per quarter hour, agent, endpoint, model, session and whether the cost is known,
  holding the sums. The page buckets by hour at the finest, so nothing it shows is lost, and the quarter hour keeps the
  half- and quarter-hour time zones on the right day. A busy session makes one row a quarter hour, not one a request,
  so a read of the page's widest window stays small in a 128 MB isolate.
- **Retention: 92 days**, t3's own `CACHE_RETENTION_DAYS` (the longest t3 keeps a transcript's usage, more than the
  page's widest range of 90 days), **and at most 50,000 rows**, oldest first, a guard against a runaway writer (a heavy
  owner makes a few hundred rows a day). Both are pruned on a write, at most once an hour.
- **Cost**: the Session's (pi-ai's, from the endpoint's model prices) when positive; else, for a relayed answer, the
  endpoint's listed model's prices; else none. A row's `UsageRecord` has `reportedCostUsd: null` then and
  `rateModel` the model's own id, so **t3's rate table prices it** (`usagePricing.ts`).

## The Usage page

`usage/readers.ts` `makeOwnUsageReader`: one scan reader per t3 usage provider (in the Shadow's
`BUILT_IN_USAGE_DRIVERS`), one source per agent (`t3flare://usage/<agent>`). t3's provider kinds are fixed
(`UsageProviderKind`), so the Durable agent, text generation and the pi CLI are all **Pi**; their sources tell them
apart (each bucket carries its source path). A model is shown as its slug, `<endpointId>/<modelId>`, so the same model
on two endpoints is two rows. Commissary's request log is no longer read for the page (escalation 1).

## Seams tested

- **Relay** (`apps/agents/test/relayUsage.test.ts`, through `handleModelRelay`): each API's recorded shapes, streamed
  in pieces that cut lines and characters; a whole JSON body and Google's JSON array; the answer byte for byte;
  unreadable answers relayed whole and unrecorded; a refusal unrecorded; a throwing record harmless; each piece passed
  on before the reader holds the next half line.
- **Durable and text generation** (`apps/agents/test/sessionUsage.test.ts`): a Session's endpoint provider answering
  over pi-ai's real Anthropic client, with its cost; an unpriced model left to the Environment; a refused request
  unrecorded; the Model proxy's answers under `anthropic`; text generation's own record.
- **Storage and the page** (`apps/environment/test/usageRecords.test.ts`, on Node's SQLite): the rollup, the split by
  agent and by endpoint, a dated model to the listed one and its endpoint price, **t3's own `UsageAggregator` and
  `parseRateTable` pricing an unpriced model** (`modelPriced`), the read window, the retention, the row cap, and
  refused entries.

## Escalations (provisional, for the orchestrator)

1. **The Usage page no longer reads Commissary's request log**, ahead of SPI-1176. With a Commissary endpoint keyed
   with the proxy's key (SPI-1175's stage endpoint, and the likely prod setup) every endpoint request was counted
   twice (seen on p1173). Its readers stay in the tree, unused by the page, for SPI-1176 to delete with the rest; the
   limit meters still read Commissary (SPI-1174's to replace). Until the hard cut, the Durable agent's answers on the
   Model proxy are recorded too (under `anthropic/<model>`, the proxy's own slugs); **a CLI agent on the Model proxy
   (the key helper's path, not the relay) is not recorded**. Alternative: keep the log beside our records until
   SPI-1176, accepting the double count.
2. **The Durable agent, text generation and the pi CLI share t3's `Pi`** (t3's provider kinds are a closed list; a
   new kind would be a Patch of the contracts). They are told apart by source, which the page's per-provider rows do
   not show; the breakdown by model does.
3. **The page's record and session counts are rows, not requests**: a row is a quarter hour of one session's answers
   on one model. Tokens and cost are exact.
4. **A relayed stream the CLI abandons mid-way is not recorded** (the reader records at the stream's end). Its
   tokens were spent (an interrupted turn's last request, for one).
5. **Retention**: 92 days and 50,000 rows (above). Both are constants in `records.ts`.

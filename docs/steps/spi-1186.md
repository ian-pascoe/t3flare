# SPI-1186: t3's commit action in the Container (with SPI-1091's acceptance case)

Report for SPI-1186, with SPI-1091 folded in (owner's decision): its acceptance case is this change's regression test.
The ticket's agent brief is the plan. Decision record: ADR-0009's SPI-1186 refinement. Upstream coupling: U6 in
[`upstream-fragility.md`](../upstream-fragility.md). Evidence: [`spi-1186/`](spi-1186/), from stage `pgitobj`
(destroyed), and SPI-1150's [`global-mise/git-gh.json`](global-mise/git-gh.json), re-run there.

## The cause

t3's commit draft (`GitVcsDriverCore.prepareCommitContext`) runs git with three variables on its own side, in a
`t3code-commit-index-*` directory of the State directory: `GIT_INDEX_FILE` (a copy of the repo's index),
`GIT_OBJECT_DIRECTORY` (an empty folder for the blobs its staging writes) and `GIT_ALTERNATE_OBJECT_DIRECTORIES` (the
repo's objects at `/w/<id>/.git/objects`, then each `alternate:` of `count-objects -v`, every entry C-quoted, joined
with `:`). The router bridged only the index. The Container's git saw an object directory that did not exist
(`fatal: not a git repository`, exit 128, which t3 reports as `prepareCommitContext.expandSplitIndex …
(not_a_repository)`), and the alternates list reached it untranslated (`gitEnvOf` translated a value only when it
started with `/w/`; this one starts with `"`).

## What changed

- **The bridge** (`apps/environment/src/agents/gitBridge.ts`, new; `processRouter.ts` uses it through `gitEnvInto`).
  - `GIT_INDEX_FILE` is bridged as before: t3's bytes copied once to `<harness>/tmp/index-<digest>/index`, the digest
    the same (SHA-256 of `<id>\0<t3 path>`, 12 bytes).
  - `GIT_OBJECT_DIRECTORY` on t3's side maps to `<harness>/tmp/objects-<digest>`, made once per draft (removed, then
    made with a marker file `info/t3flare-draft`, so the folder reaches the Container's copy whether or not an empty
    folder would). The draft's later commands reuse it. Its blobs never reach the repo's object store.
  - "t3's side" is a path the State directory holds, or a file t3 has yet to make in a folder there (a repo with no
    index yet). Paths in `/w`, Workspace paths and relative ones are left alone.
  - **Cleanup.** Each bridge watches t3's own path (or its folder when t3 made no file). On every routed git command
    (t3's status polls make it prompt) the bridge removes the folders of drafts whose t3 path is gone: t3's scope
    ended. A draft in flight still has its t3 path, so its folders are never removed. The map is in memory, so a
    Workspace's own leftovers from an earlier isolate (`index-*`/`objects-*` that no live bridge holds) are swept on
    its first draft in this isolate. A bridge registers before it makes anything, so a sweep never takes it. A bridge
    that fails to make its folder is forgotten, so the next command makes it again. The old 30-minute map expiry,
    which re-seeded the index of a draft older than that, is gone.
  - The router trace (`GET /_t3flare/agents/router-trace`) lists the live bridges (`gitBridges`).
- **The alternates list** (`gitRoutes.ts` `alternatesInto`, used by `gitEnvOf`). Each entry is read as git reads it
  (C-quoted up to its closing quote, octal escapes as UTF-8, otherwise up to the next `:`), translated on its own (a t3
  path of this Workspace as the Workspace's path; another Workspace's left as `intoWorkspace` leaves it, which a
  scratch checkout's commands need), and written quoted, joined with `:`. An entry in the State directory is dropped
  and logged (`git-alternate-dropped`); with none left the variable is not sent. Other entries outside `/w` came from
  the Container's own `count-objects` and are kept.
- **The draft's first two reads** (`apps/agents/src/workspace/gitDirReads.ts`). `rev-parse --git-path index
  --git-path objects` and `count-objects -v` stay passive. They join the Workspace DO's first-read allow-list and its
  priming (ADR-0009's SPI-1186 refinement; provisional, see Escalations). `count-objects` is keyed on `.git` alone
  (`GIT_DIR_ONLY`), so primed answers hit.
- **Acceptance** (`scripts/lib/t3Commit.ts`, new; `lib/realTurn.ts`). `--real-turn` now commits the turn's edit through
  t3's commit action (`git.runStackedAction`, `action: "commit"`, `filePaths: ["src/greeting.txt"]`, a message), and
  checks that the commit t3 reports is HEAD and lists the file. With `--push`, step 4's `commit_push_pr` drafts the same
  way. The bump runs `--real-turn`, so every nightly checks it (SPI-1091).
- **Stage** `pgitobj` in `STAGES`; `scripts/pgitobj.ts` makes the evidence below. `pmise.ts`'s git-gh note follows the
  outcome.
- **Docs.** U6 in the upstream-fragility register names the new lean on t3's internals: the draft's directory and
  scope, the three variables, the alternates list's shape and where t3 sets them, the review index, and the two reads
  the allow-list matches exactly. ADR-0009 has the refinement. `global-mise.md`'s SPI-1186 notes are updated.

## Readings and limits

- **T6.** In every run the draft's two reads ran nowhere: cache or last answer. t3's status poll left the stopped
  Container stopped. What started it was an action: in `stopped.json` (final run) and `fresh.json` the draft's
  `update-index`; in an earlier `stopped` run, t3's own upstream fetch (`refreshStatusUpstreamIfStale`), which
  t3's commit action runs first when the upstream is stale.
- **The allow-list path did not run on the stage.** A Workspace a client has watched is primed by t3's status refresh
  (its upstream fetch is an action), so `fresh.json`'s reads already had answers. The allow-list covers a Workspace with
  no routed action since its clone; only `gitDirReads.test.ts` covers that decision.
- **A never-watched Workspace still cannot commit while its Container is stopped**, as before this change. A first
  `pgitobj fresh` run, with no client watching before the stop, failed at t3's `statusDetails.status`: a status
  shape with no answer at all (ADR-0009's "a read with no earlier answer fails fast"). That is before the draft and
  not this change.
- **git-gh's status** read `hasPrimaryRemote: false` once on the fresh `pmise` clone, its first status with the
  Container stopped (stale reads); read again it was true.
- **Checks.** `pnpm run check` passes at `2d494f9` (34/34); the commit after it changes only this line.

## Escalations (provisional decisions)

1. **The draft's two reads joined the Workspace DO's first-read allow-list** (ADR-0009 refinement, `gitDirReads.ts`).
   The brief says the commit path's passive reads must not start a stopped Container. They are still passive, and are
   primed, so in every stage run they started nothing. But for a Workspace never primed they may now start it once,
   as the worktree launch's reads may. The reason: without it, a commit in such a Workspace fails at its first read,
   every time. The commit starts the Container at its first write anyway. The alternative is to keep them stale-only
   and accept that failure. To undo it, drop the two entries.
2. **Cleanup by t3's own path, not by a timer.** A bridged folder goes when t3's temporary path is gone from the State
   directory (t3's scope ended), or on the Workspace's first draft after an isolate change. There is no age limit:
   a draft hung in flight keeps its folders until its scope ends or the isolate goes.
3. **Alternates outside `/w` that the State directory does not hold are kept**, on the reasoning that they came from
   the Container's own `count-objects -v`. Only entries in the State directory are dropped.

# SPI-1176: The hard cut: remove the Model proxy

Every agent now reaches models only through the owner's Model endpoints ([ADR-0034](../adr/0034-model-endpoints-are-the-owners-set-in-the-harness-panel.md),
now accepted; [ADR-0012](../adr/0012-all-model-access-goes-through-the-model-proxy.md) superseded by it;
[ADR-0016](../adr/0016-no-vendor-credential-enters-a-container-and-cli-agents-reach-the-model-proxy.md) revised). The
Model proxy, its key, the CLI agents' key helper, the Commissary usage and limit readers, the proxy failure classifier and
the static model list are gone. An Environment with no endpoint is in the **setup state**: every provider says so and
points to the Harness panel. The owner's prod steps are in [`spi-1176-owner-setup.md`](spi-1176-owner-setup.md); the
guide that replaces `docs/model-proxy.md` is [`docs/model-endpoints.md`](../model-endpoints.md).

## What changed

- **Session (agents Worker)**: no proxy provider in pi's model registry and no catalog; the session's models are the
  endpoints' (`session/models.ts` `sessionModels`). The proxy classifier and Commissary's fault texts went; failures are
  the Model relay's per-API classification (SPI-1172). Prompt suggestions use the endpoints' side models; `web_search`
  runs on an Anthropic Messages endpoint (`#searchTarget`). The Guardian and Advisor resolve their model setting against
  the endpoints (`default`/`inherit`; a proxy-era slug reads as `default`). `proxyLimits.ts` became `modelLimits.ts`.
- **Workspace (agents Worker)**: the key route `/t3flare/model-key` (now 404), its per-process nonces, the
  `COMMISSARY_CONTAINER_API_KEY` binding and the sync guard's key entries went (`workspace/modelKey.ts` deleted).
- **Pi Durable (Environment)**: the provider snapshot lists the endpoints' models only; with none it is t3's `warning`
  status with a message pointing to the Harness panel (`provider/readiness.ts` `readinessOf`). A proxy-era selection
  (`anthropic/…`, any slug no endpoint has) falls back to the default model, the first endpoint's first model
  (`adapter.ts` `modelOf`). A turn that still finds no model fails "No Model endpoint is set up: add one in the Harness
  panel …" (`differ.ts` `failureOf`, reading the setup state when pi-durable's settlement names no model).
- **CLI agents**: the proxy modes, key helper and nonce went from every profile. A spawn with no endpoint for the CLI's
  API is refused naming what it needs (`cliProfiles.ts` `noEndpointFor`), and t3 shows that text (the wrapper's
  `withSpawnRefusal` puts a `ProviderSetupError` under t3's open error). Each CLI's proxy-era model ids fall back to its
  default endpoint model (`claudeModelId`, `opencodeModelId`, `codexModelRoute`, `piLineToPi`). `codex exec` runs on the
  relay. The sandbox image lost `t3flare-model-key` and `t3flare-claude-key`.
- **t3's picker**: patch 0006 (renamed `0006-endpoint-models-are-not-retained.patch`) now covers `codex`,
  `claudeAgent`, `opencode` and `pi` as well as `piDurable`: stock t3's registry keeps a provider's earlier models when a
  refresh lists fewer or none (always for `claudeAgent`; for Codex on a `warning`; for pi while its auth is `unknown`),
  and persists them. Without it a provider in the setup state still lists the models it had, and prod's Claude picker
  would keep the proxy's ~120 models after the cut (U75's open item, SPI-1168 escalation 3).
- **Text generation**: no proxy; its default and a proxy-era setting resolve to the endpoints' small model
  (`defaultSmallModel`).
- **Usage**: Commissary's usage reader, its limit source and the count exclusion went; the Usage page is t3flare's
  own records and the subscription endpoints' meters. That ends U84's P3 double count. U58 is retired; its live
  leans moved to U86.
- **`packages/models`**: `catalog.ts`, `models.json`, `proxyFailure.ts` and their fixtures deleted; `lists.ts` keeps
  `parseList`/`realIdOf` for the endpoints' model discovery. `endpoints.ts` gained `isRetiredSlug`, `defaultModelSlug`,
  `defaultSmallModel`, `SETUP_HINT`, `NO_ENDPOINT_MESSAGE`.
- **Harness settings**: the Guardian, Advisor and web-search model settings are text (`<endpointId>/<modelId>`,
  `default`, `inherit`), not the static list's enum.
- **Deploy and CI**: `alchemy.run.ts` binds no `MODEL_PROXY_*` or `COMMISSARY_*`; the workflows pass none; the deploy
  plan refuses `--no-model-proxy` (nothing to turn off); `modelEndpointSpec` no longer derives an endpoint from
  `MODEL_PROXY_*`; `infra/github.ts` (`ci:setup`) removes the proxy's variables and secrets it once set; `bump.ts` and the
  acceptance scripts need no proxy.
- **Docs**: ADR-0034 accepted, ADR-0012 superseded, ADR-0016 revised, ADR-0015/0018/0028 amended; GLOSSARY drops Model
  proxy and Key helper and revises Subscription; `docs/model-proxy.md` → `docs/model-endpoints.md` with the setup step;
  upstream-fragility: U14, U25 (retired), U32, U53, U58 (retired), U66, U69, U75, U76, U78, U79, U80, U84, T8 updated and **U85**, **U86** added
  (the setup state and the fallback of old selections); README, parity, pi-parity, scope-audit, cost updated.

## Removed, and what was deliberately kept

Removed: `MODEL_PROXY_URL`, `MODEL_PROXY_API_KEY`, `COMMISSARY_CONTAINER_API_KEY`, `COMMISSARY_MANAGEMENT_*`,
`COMMISSARY_ACCESS_*`, `COMMISSARY_USAGE_PRINCIPALS` (code, `alchemy.run.ts`, workflows, `deployPlan`, `infra/github.ts`);
the key helper (`t3flare-model-key`, `t3flare-claude-key`, the `/t3flare/model-key` route, nonces, `modelKey.ts`); the
Commissary usage and limit readers (`usage/commissary.ts`, `commissaryCount.ts`); the proxy failure classifier
(`proxyFailure.ts`); the static model list (`models.json`, `catalog.ts`); `scripts/models.ts` and `scripts/p1173.ts`
(proxy-only harnesses); `test/docker/cli.docker.test.ts` (it ran the CLIs on the proxy).

Kept, and why:

- **Commissary as an ordinary endpoint and a direct MCP server**: the guide and owner note use it as the example of an
  Anthropic Messages (and OpenAI Responses) endpoint, and as an MCP server added in the panel. `scripts/commissaryMcp.ts`
  now reads `T3FLARE_MCP_API_URL`/`KEY`.
- **Wire and storage names**: the session protocol's `ProxyRecord`/`turn.proxy`, the `proxy-fault` log kind and the
  `proxy-limits` extension name; renaming them touches the agents–Environment wire for no behaviour.
- **The stage harnesses that still run** (`p1162`, `p1164`–`p1166`, `p1168`–`p1172`, `p1174`, `p1175`): they use
  Commissary as an ordinary endpoint, its URL and key read from `MODEL_PROXY_URL`/`MODEL_PROXY_API_KEY` in the shell
  (script input only). Deleted in review round 1: `pvars.ts`, `p1163.ts`, `p1167.ts`, and `pbatch2`'s Commissary
  parts (each expected the proxy, the key helper or Commissary's readers).
- **`tools.ts`'s check that `/t3flare/model-key` never answers 200**: still true (404), a guard against the route's return.
- **`opencode-key-plugin`**: it now reads the relay handle (SPI-1169); only its comment names the key helper.
- **Old storage**: the proxy catalog's KV keys in Session DOs stay (unread); no migration deletes them.

## Escalations (assumed provisionally)

1. **`web_search` runs only on an Anthropic Messages endpoint with an API key or no auth**, and its request writes no
   usage record. Recommendation: accept; a subscription-endpoint search and its usage record are a follow-up.
2. **Text generation's default is the endpoints' small model** (`defaultSmallModel`: SPI-1163's small-model pick,
   `defaultTextModel`, else the default model), with no proxy model to fall back to.
3. **`cli.docker.test.ts` removed**: it ran each CLI on the proxy. The relay docker tests (`claudeRelay`,
   `opencodeRelay`, `piRelay`) cover Claude Code, OpenCode and pi on endpoints; **Codex's local egress proof is lost**.
   Recommendation: a follow-up ticket for a Codex relay docker test.
4. **The deploy plan refuses `--no-model-proxy`** rather than ignoring it, so a stale invocation fails loudly.
5. **The Guardian, Advisor and web-search model settings are text**, validated against the endpoints at use, not an
   enum; a proxy-era value reads as `default`.
6. **Stage harnesses**: the ones that still run kept; `scripts/models.ts`, `p1163`, `p1167`, `p1173`, `pvars` and `pbatch2`'s usage part deleted (revised in review round 1).
7. **Wire names kept** (`ProxyRecord`, `turn.proxy`, `proxy-fault`, `proxy-limits`); old catalog KV keys left in storage.
8. ~~A Codex thread started on the proxy cannot move to an endpoint~~: wrong; the upgrade run resumed one on its
   native thread (review round 1, item 11).
11. **An old selection runs on its model's endpoint, else the default** (`retiredSelectionSlug`, review round 1). The
   default itself stays the first endpoint's first model; with a list that names dead models first (Commissary's), a
   `default` thread runs on one. Recommendation: keep it, as the owner orders and narrows the list, and the owner note
   says so; or (a follow-up) prefer a model pi-ai's catalog knows, as Claude Code's aliases now do.
12. **Claude Code's `sonnet`/`opus` aliases prefer a model pi-ai's catalog knows** (review round 1): SPI-1168's
   alias rule, changed here because the upgrade broke on it.
13. **`T3FLARE_MODEL_ENDPOINT` takes a list** (one secret, not one per API) for the bump's coverage.
9. **Patch 0006 extended to the CLI drivers** (no Layer reaches t3's registry merge; a Shadow would copy its ~1,200
   lines, ADR-0001). It changes t3 for every driver t3flare runs, so a CLI's picker can no longer hold a model its
   endpoints stopped listing.
10. **Commit `0466c8c`** (a p1176.ts fix) also carries the deletion of `docs/model-proxy.md`; harmless, noted for the
   reviewer.

## Linear drafts (for the orchestrator to post at merge)

**SPI-1045 — cancel.** Reason: "Obsolete after SPI-1176 (the hard cut). The key helper and `t3flare-model-key` are gone;
OpenCode's plugin now sends its process's model relay handle (SPI-1169), which does not rotate during a process's life,
so there is no key to re-ask after a 401. A 401 from an endpoint is the relay's classified credential failure (SPI-1172)."

**SPI-1041 — comment.** "SPI-1176 removed the Model proxy, so the allowlist this ticket describes changes: a CLI's model
traffic no longer leaves the Container for a model host. Every model request goes to `computer.internal` (the model
relay, SPI-1167–1170), which forwards it to the owner's endpoint from the Worker. The allowlist for model traffic is
therefore `computer.internal` only. Note: `cli.docker.test.ts`, the local egress proof for the CLIs on the proxy, was
removed at the cut; the relay docker tests cover Claude Code, OpenCode and pi, but Codex has no local egress test now."

**SPI-1042 — comment.** "After SPI-1176 no model key ever enters a Container: the key helper and the Container key
(`COMMISSARY_CONTAINER_API_KEY`) are gone, and CLIs hold only a per-process relay handle. The sync guard and leak scan
now look for git tokens, the endpoints' API keys (by value in the DO, by hash in the Container) and the sign-ins' tokens
(by hash, SPI-1171). The `state.db` issue stands for those (a git token written to /workspace), but the commonest case,
a model key, cannot occur."

**SPI-1106 — comment.** "SPI-1176 removed the key helper, so the option this ticket weighs (a launcher that fetches the
Container key with the process's nonce) no longer exists. Owner's decision stands: env-key ACP registry agents stay
refused. If revisited, the shape would be the relay handle in the agent's environment (the relay forwards to an
endpoint), which still exposes the handle to every command the agent runs; the registry's refusal text now names the
handle, not the key helper."

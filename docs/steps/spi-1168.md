# SPI-1168: Claude Code through the model relay

Claude Code threads run on any Anthropic Messages Model endpoint through the model relay (SPI-1167). Decision record:
[ADR-0016](../adr/0016-no-vendor-credential-enters-a-container-and-cli-agents-reach-the-model-proxy.md)'s SPI-1168
refinement; [ADR-0034](../adr/0034-model-endpoints-are-the-owners-set-in-the-harness-panel.md) item 7; fragility
[U70](../upstream-fragility.md#u70-claude-code-on-model-endpoints-through-the-model-relay-spi-1168).

## How Claude Code handles two endpoints

Claude Code has **one base URL per process** (`ANTHROPIC_BASE_URL`). It has no per-model base URL: `modelOverrides`
only maps model ids, and `modelPicker` rows only describe them (Claude Code 2.1.322's settings schema). t3 resumes a
thread in the running process on a model change and never asks the adapter's `planSelectionTransition` (measured on
p1167), so a restart per endpoint cannot be planned from the driver either.

The design (provisional, escalation 1): **one base URL for every endpoint**. The relay gets a **model-routed URL**,
`http://computer.internal/t3flare/model/_`. Claude Code's models are the endpoints' slugs (`<endpointId>/<modelId>`),
which it sends verbatim as the body's `model`; the relay finds that top-level member, sends the request to the endpoint
the slug names with the model's own id in its place, and passes the rest of the body byte for byte. The handle's scope
judges the endpoint exactly as a path's. A switch between two endpoints' models stays in the thread's process and its
native Claude session, and the background model can be on any of the endpoints.

## Where the handle is (the brief's question)

The Workspace DO puts the handle in the process's environment, as for Codex. The launcher execs claude-agent-acp
(`node --require claude-handle-unset.cjs …`): the preload deletes `T3FLARE_MODEL_HANDLE` from `process.env` before
claude-agent-acp runs, so the `claude` it starts, and Claude's Bash, hooks and helpers, do not inherit it. The kernel's
copy of the start environment (`/proc/<pid>/environ`) keeps it; `apiKeyHelper` (`t3flare-claude-handle`) reads it from
there, by the launcher's pid and start time kept in the process's home (`acp.pid`: not the handle), once it has checked
that the pid is still that claude-agent-acp (start time and command line; it fails closed otherwise). No file holds it.

**What this does not do.** It keeps the handle out of environments and files, not out of reach of the Container's
commands. `/proc/<pid>/environ` is readable by any process of the same uid, and everything in the Container runs as
root. Claude's Bash keeps `T3FLARE_EXEC`, so a command it runs can run `t3flare-claude-handle` and print the handle (or
read the launcher's environ directly), and it can set `T3FLARE_EXEC` to another Claude process's directory and get that
process's handle. That is the same class as Codex's exposure (a Codex shell can read its parent's
`/proc/<pid>/environ`), not wider: in both, a command can spend through a live process's handle, for that process's
endpoints, until the process exits, and none can take an endpoint's key out of the Container (ADR-0016's residual).

Proved on p1168: the processes whose environment holds the handle are exactly `setsid --wait
/opt/t3flare/bin/claude-agent-acp` and the claude-agent-acp node; none of the 3 `claude` processes; no file in the
process homes, `/etc/claude-code`, `/root`, `/tmp` or the repo; a full-access turn's `env > file` has `T3FLARE_EXEC` and
no handle. The same is checked by `test/docker/claudeRelay.docker.test.ts` with the real image layer, together with the
helper's refusal of a launcher record that names another process, or the right pid with another start time. The
launcher and helper were also run in `ubuntu:26.04` (uutils coreutils 0.10.0).

`x-api-key` vs `authorization`: with `apiKeyHelper`, Claude Code sends the helper's output in **both**; the relay takes
the handle from either (`KEY_HEADERS`) and forwards neither.

## Escalations (provisional, as assumed)

1. **The model-routed URL reads the request body** (its top-level `model`) to choose the endpoint, and rewrites that
   one member. ADR-0016's SPI-1167 text said the body passes unchanged; this is routing, not protocol translation, and
   only on `…/model/_`. Alternatives: a process restart per endpoint (t3 never asks for one; it would need a Shadow
   or Patch of t3's turn start, and the background model would still be stuck on one endpoint), or refusing a switch
   across endpoints as Codex does (fails this ticket's switch criterion). Recommendation: accept. The cap is 16 MiB;
   the body is held in one buffer while it is scanned (review round 1).
2. **The relay-or-proxy choice is the Environment's**: with any Anthropic Messages endpoint, every Claude Code process
   runs on the endpoints, and the Model proxy's models no longer work in Claude Code (an earlier Claude thread on an
   `anthropic/…` model gets "The agent did not accept the model"). Reason: the managed settings file is the
   Container's, shared by every Claude process, so a per-session choice would let one process's settings overwrite
   another's. This is the hard cut arriving early for Claude Code only (ADR-0034 item 6 says the proxy's models keep
   working until SPI-1176). Recommendation: accept; the owner adds Commissary as an endpoint. An Anthropic Messages
   endpoint that lists no model does not count (review round 1). ADR-0034 item 6 records the exception, pending the owner.
3. **t3 keeps Claude's earlier models in the picker** (U70): the proxy's models listed before the first Anthropic
   endpoint stay after the endpoints' until the Environment restarts its registry (p1168: 124 rows, 121 the proxy's).
   Picking one is refused as in 2. Fixing it needs a Shadow or Patch of `ProviderRegistry.ts`
   (`shouldRetainMissingProviderModels`), as patch 0006 did for Pi Durable's removed models (U66). Recommendation:
   a follow-up, or leave it to the hard cut, which empties the proxy's list.
4. **The background model's fallback**: when the text-generation model is not an Anthropic Messages endpoint's model,
   it is the endpoints' small model (text generation's default rule over them), else the first endpoint's first
   model. Claude Code's sonnet/opus aliases (`ANTHROPIC_DEFAULT_SONNET_MODEL`, `…_OPUS_…`) are not set: a subagent
   asking for one by alias gets the routed URL's 400. t3 always names the model.
5. **The handle's holders include `setsid`**, the launch chain's parent (processHost's `exec setsid --wait`), whose
   environment is the launcher's. Codex's is the same. Not a new exposure.
6. **Claude Code's failure texts still name the Model proxy's key** (`cliPromptFailure`: "Check the deploy's
   COMMISSARY_CONTAINER_API_KEY") for a 401 on an endpoint. Left for SPI-1171 (sign-ins), which reworks the key's
   failures.
7. **An endpoint added while a Claude process runs** is in its handle's scope only from its next process (403 until
   then), as for Codex (SPI-1167 item 7). The Container's managed settings follow the newest spawn.

## Review round 1

1. **Glossary**: **Managed settings** describes both modes (the relay's routed URL with the handle helper, or the
   proxy with the key helper); **Model-routed URL** is a new entry.
2. **Exposure**: ADR-0016's item 3, "Where the handle is" above and U70 say plainly that the handle is out of
   environments and files, not out of reach: same uid reads `/proc/<pid>/environ`, Claude's Bash can run the helper,
   and can point `T3FLARE_EXEC` at another process's directory. Same class as Codex, not wider.
3. **Body memory and order**: the handle is checked before the body is read (`authorize` with no endpoint answers
   `known`; a forged handle gets 401 with the body unread, tested with a body that records whether it was pulled, and
   the test fails when the order is reversed). A declared `Content-Length` over the cap is 413 before anyone is asked.
   The scanner works on bytes (`routedBody.ts`), nests at most 512 levels, and rewrites the slug in place: one buffer
   per request. **The cap is 16 MiB**: one copy per request leaves room for several in a 128 MB isolate, and Claude
   Code's requests are far smaller (84 KB on p1168); a larger one gets 413, which Claude Code reports.
4. **An Anthropic endpoint with no models** is not Claude's (`claudeEndpoints`): alone it leaves Claude Code on the
   proxy. Tested in `claudeEndpoints.test.ts` and `claudeSpawn.test.ts`.
5. **The pid file** holds the launcher's pid and start time; `t3flare-claude-handle` checks both and the command line
   before reading the environ, and fails closed.
6. **Tests**: the scanner (`apps/agents/test/routedBody.test.ts`: an escaped `model` key, an escaped quote in a key, a
   BOM, nesting at and past the limit, the in-place rewrite, the cap); the spawn's wiring
   (`apps/environment/test/claudeSpawn.test.ts`: relay mode, proxy mode, refused with neither); the launcher, preload
   and helper in `test:docker` (`test/docker/claudeRelay.docker.test.ts`, with a stand-in model relay in
   `keyhost.mjs`; it needs no proxy key). It passed, and failed with the preload disabled. It found that Claude Code's
   own default model (`claude-opus-5-5`) is not a slug: t3 always writes the session's model before a turn, so this
   matters only if it stops (U70).
7. **ADR-0034 item 6** has the Claude Code exception, pending the owner.
8. **`pnpm run check`** passed: run from the repo root with `NPM_CONFIG_WORKSPACE_DIR` set, on a248da3 (this round's
   code) plus this round's docs: `vp run: 34/34 successful`. The agents Worker's tests: 613 passed, 1 skipped, in 67
   files. The Environment Worker's: 703 passed, in 91 files. Round 0's check passed too, on 4a97ce1 (699 tests in 90
   files). The stage's two endpoints share one upstream (see the evidence section above).

Optional items done: one resolved `ClaudeMode` (`claudeModeOf`) used by the launch and the managed settings, whose
signature is now `(mode, relayServers)`; the narrowing 404 is gone and the one remaining narrowing branch logs; the
routed names (`routedBody`, `routedRequest`, `unnamed`); `snapshotOf` reads the proxy's models once. Left:

# SPI-1160: Commissary's MCP tools become a direct server the owner adds (report)

Date: 2026-11-14. Branch `spi-1160-commissary-direct-mcp`, from `main` at 6bc3cfc. t3code is untouched. No separate
plan (the ticket's decisions are the Model endpoints decisions of 2026-11-13). Decision record: the SPI-1160 refinement
of [ADR-0028](../adr/0028-mcp-tools-reach-agents-through-the-environments-mcp-host.md). Evidence:
[`spi-1160/`](spi-1160/). Stage harness: `apps/environment/scripts/commissaryMcp.ts`. Throwaway stage `p1160`,
destroyed at the end.

## What was built

The MCP host no longer reads the Model proxy's settings. Commissary's MCP endpoint is added in the Harness panel like any
other direct server, signed in with an `x-api-key` header the owner types once.

- **Gone**: the `commissary` server kind (`ServerKind` is `"direct"`), `defaultCommissary`, `CommissaryConfig` and the
  host's `commissary` dependency, `toolsKeyOf`, and the `COMMISSARY_TOOLS_URL` and `COMMISSARY_TOOLKITS` bindings on
  the Environment DO. Neither binding was set in `alchemy.run.ts`, the workflows or `infra/github.ts`, so deploy wiring
  and CI had nothing to remove. `MODEL_PROXY_*` and the key helper are untouched (SPI-1176's).
- **The MCP server set is what the owner added.** `mcpServersOf` no longer implies a Commissary entry. A new
  Environment offers no MCP server until he adds one.
- **Old settings load.** A stored Harness settings document that still names the built-in `commissary` server loads
  without it: the entry is **dropped** (not kept inert). The next change to the server set saves the set without it.
  The dropped kinds are named in `RETIRED_SERVER_KINDS`; `kind` stays on the setting because stored documents carry it.
- **An added server starts fresh** (review round 1). Adding a server forgets the inventory and protocol state (era,
  session id) kept under its name, from a removed server or the retired built-in, so no old tool list shows as
  available and no old session id goes out with the new key.
- **The name `commissary` is free** (no longer reserved, and no longer unremovable), so the owner can re-add Commissary
  under it and its tools keep their names (`mcp__commissary__<tool>`).
- **Error texts**: a refused call no longer says "Commissary refused the tools key (MODEL_PROXY_API_KEY)"; it gets the
  ordinary "the MCP call failed … may have run" text.
- **The panel** drops the per-server kind tag (every server is a direct one now): each card shows its URL, its sign-in
  and a Remove button.
- **The Durable agent's tool descriptions** no longer say "through Commissary" or "Commissary's toolkits".
- **Docs**: ADR-0028's SPI-1160 refinement; ADR-0012's tools-key sentence marked superseded; `docs/model-proxy.md`'s MCP
  section now says how to add Commissary by hand (panel and admin API); GLOSSARY's MCP server, Direct server and MCP
  relay entries; `docs/parity.md` and `docs/pi-parity.md` rows.
- **Stage scripts**: `scripts/commissaryMcp.ts` (this ticket's evidence). `scripts/panel.ts`'s seed now adds Commissary
  as a direct server before testing it.

## Decisions (accepted by the orchestrator in review round 1)

1. **Dropped, not inert.** The ticket allowed either. Keeping the old entry inert would hold the name the owner re-adds
   Commissary under, and an entry with no URL can never work. Its inventory and protocol state stay in storage under its
   name until a server is added under it, which forgets them (review round 1).
2. **`commissary` is no longer a reserved name**, so tool names stay `mcp__commissary__…` after the owner re-adds it.
   Alternative: keep it reserved and have him pick another name (tool names would change).
3. **The panel's kind tag is removed** rather than showing "Direct" on every card.
4. **The evidence used the Model proxy key as Commissary's MCP key**, as the orchestrator asked. `docs/model-proxy.md`
   recommends a key of its own with a tool scope; that choice is the owner's.

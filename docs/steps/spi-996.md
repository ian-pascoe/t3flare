### Plan mode and the proposed plan

pi-durable has no plan primitive, so a tool stands in for one, as Claude Code's `ExitPlanMode` does:

- **`propose_plan({ plan })`** (`apps/agents/src/extensions/plan.ts`). In plan mode it answers with Claude's adapter's
  text ("captured … stop here") and `control.terminate`, so the plan ends the run with no further model request.
  Outside plan mode it refuses and changes nothing.
  - It is offered in both modes, so the tool list and the prompt cache stay the same.
  - It is never deferred (`ALWAYS_OFFERED`); scripts cannot call it (`callers: ["model"]`).
  - The Guardian lets it through.
  - A plan-mode section tells the model to call it once the plan is decision complete, with a `#` title.
- **The differ** (`emitProposedPlan`) shows a taken call as a `plan` node, a `proposed_plan` turn item and an `active`
  plan artifact. That is the shape t3's Codex and Claude adapters emit, and the status t3's Orchestrator requires to
  implement a plan. The plan is read from the call's arguments, since `details` are cut at 64 KiB in a push.
  - A revised plan supersedes the session's last one, as Claude's adapter does.
  - A default-mode turn forgets the last plan (`forgetProposedPlan`), so a plan t3 completed is never marked superseded.
  - A refused call stays a tool item with its error.

### Streamed command output

- The Session pushes each running call's retained output (`pi.live.tools[].output`): its last 8 KiB
  (`TOOL_LIVE_OUTPUT_BYTES`), and none once done.
- The differ streams what is new for `bash` and the Terminal commands as `command_output.delta`, on the command item's id.
  - The new part is what follows the part two pushes share (`sharedTail`), so a sliding tail streams correctly.
  - Output that a push missed is marked `[… earlier output not streamed …]`.
  - The result's output still lands on the item, as with Codex.
- **Gap (SPI-1099).** A command on the Worker Shell gets its output only at exit, from computer's RPC, so nothing streams
  there. bash routes a `sleep` loop to the Worker. Container commands stream.
- Terminal tools answer with a settled screen: a call returns once the screen is quiet. They stream only if a call
  itself runs long.

### Prompt suggestions

t3's contract supports them for any provider: the adapter's `promptSuggestions` flag and the `prompt_suggestion.updated`
event.

- After a completed turn on a thread that is not delegated, with the flag on, the adapter asks the Session
  (`suggestPrompt`).
- The Session gives Haiku the turn's request and final answer, 4,000 characters each, with t3's
  `CODEX_PROMPT_SUGGESTION_PROMPT`. It uses its own models, outside the turn's usage-limit records.
- It is best effort: an error, an empty reply or an overlong one gives nothing. A suggestion that arrives after the next
  turn has started is dropped.
- The flag is off by default in t3, so this costs nothing until the owner turns it on.
